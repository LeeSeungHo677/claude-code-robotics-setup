# 로봇 알고리즘 설계 · 구현

논문 구현과 **현장에서 도는 알고리즘**은 다른 작업이다.
여기서는 후자를 만드는 절차를 다룬다.

## 0. 먼저 물어야 할 것

새 알고리즘을 만들기 전에:

- **기존 것으로 안 되는 이유가 무엇인가?** 구체적 실패 사례를 댈 수 있어야 한다.
  "더 좋을 것 같아서" 는 이유가 아니다. 대부분의 경우 기존 알고리즘의 **튜닝이나
  입력 데이터 품질** 문제이지 알고리즘 문제가 아니다.
- **성공을 무엇으로 판정할 것인가?** 숫자와 임계값을 먼저 정한다.
- **계산 예산은 얼마인가?** 온보드 CPU/GPU/지연 한도. 이게 알고리즘 선택을 대부분 결정한다.
- **실패했을 때 로봇은 무엇을 해야 하는가?**

이 넷에 답하지 못하면 아직 구현할 단계가 아니다.

## 1. 베이스라인부터 세운다

**이것을 건너뛰면 나중에 개선을 증명할 수 없다.**

- 기존 오픈소스를 **내 데이터·내 로봇**에서 돌려 숫자를 확보한다.
- 그 숫자가 요구사항을 이미 만족하면 → 새로 만들 필요가 없다. 여기서 끝내는 것이 최선이다.
- 만족하지 못하면 **어떤 항목이 얼마나 부족한지**가 새 알고리즘의 목표가 된다.
- 베이스라인 실행을 스크립트로 만들어 언제든 재실행 가능하게 둔다.

## 2. 설계

- **문제를 쪼갠다.** 인지 / 추정 / 결정 / 실행 중 어디를 바꾸는 것인가.
  전부 새로 만들려 하지 않는다. 한 모듈만 교체 가능한 구조로 설계한다.
- **가정을 명시적으로 적는다.** 평면 가정, 강체 가정, 마르코프 가정, 센서 노이즈 분포,
  정적 환경 가정. **현장에서 깨지는 것은 알고리즘이 아니라 가정이다.**
  각 가정이 깨졌을 때 어떻게 되는지도 함께 적는다.
- 실시간성이 필요하면 **최악 계산량**을 먼저 계산한다. 평균이 아니라 최악.
- 수치 안정성을 검토한다: 조건수, 발산 조건, 특이점, 0 나눗셈, 각도 wrap-around.

## 3. 구현

- **참조 구현을 먼저 만든다** — 느려도 좋으니 명백히 맞는 버전.
  최적화 버전은 이것과 결과를 대조하며 만든다. 처음부터 최적화하면 틀린 것을 빠르게 실행하게 된다.
- **결정론적으로 만든다.** 시드 고정, 스레드 수 고정 옵션. 재현 불가능한 알고리즘은 디버깅할 수 없다.
- **중간 산출물을 전부 발행/기록**한다 — 잔차, 반복 횟수, 수렴 여부, 후보 수, 기각 사유.
  이 값들이 없으면 실패 원인을 추정만 하게 된다. 나중에 끄면 되니 처음부터 넉넉히 넣는다.
- **실패를 명확히 반환**한다. 수렴 안 했는데 그럴듯한 값을 내보내는 것이 최악이다.
- 단위·좌표계·부호를 타입이나 이름에 박는다.

## 4. 검증

```
단위 테스트(수학 성분)  →  합성 데이터  →  기록 데이터(rosbag)  →  시뮬  →  실기 저속  →  실기
```

- **합성 데이터로 정답을 아는 상태에서 먼저 맞춘다.** 여기서 안 맞으면 구현 버그다.
- 기록 데이터(rosbag)로 **오프라인 재현**이 가능해야 한다. 실기에서만 검증하면 반복이 불가능하다.
- **ablation**: 새로 넣은 요소를 하나씩 빼면서 각각이 실제로 기여하는지 확인한다.
  기여하지 않는 요소는 뺀다 — 복잡도는 비용이다.
- **실패 케이스를 모아 회귀 세트**를 만든다. 개선할 때마다 이 세트를 다시 돌린다.
- 성능은 **N회 반복의 분포**로 말한다. 평균과 최악값을 함께.

## 5. 배포 판단

- 기존 알고리즘 대비 **어떤 조건에서 좋아지고 어떤 조건에서 나빠지는지** 표로 정리한다.
  모든 면에서 좋아지는 경우는 거의 없다.
- 전환 시 롤백 경로를 준비한다. 파라미터 하나로 예전 알고리즘으로 돌아갈 수 있게.
- 현장 투입 후 **지표를 계속 수집**한다. 랩에서 좋았던 것이 현장에서 나쁜 경우가 흔하다.

# 로봇 종류별 고려사항

같은 문제도 로봇 종류에 따라 설계가 달라진다.

## AMR / AGV (모바일 로봇)
- **비홀로노믹 제약**이 계획을 지배한다. 차동/아커만/메카넘 중 무엇인지가 알고리즘 선택을 바꾼다.
- 상태는 대개 (x, y, θ) — 저차원이라 파티클 필터·격자 탐색이 실용적이다.
- 지배적 실패 요인: 로컬라이제이션 드리프트, 동적 장애물, 좁은 통로, 바닥 재질 변화.
- 안전이 **속도와 정지 거리**로 환원된다. 알고리즘 지연이 곧 안전 마진이다.
- 관련: `nav2`, `state-estimation`, `slam-algorithms`, `motion-planning`

## 매니퓰레이터 (로봇 팔)
- **고차원 설정 공간**(6~7 DOF) — 격자 탐색이 불가능하다. 샘플링 기반이 기본.
- 여유자유도가 있으면 null-space 로 부가 목적(관절 한계 회피, 자세 유지)을 넣는다.
- 특이점과 관절 한계가 **작업공간 전체가 아니라 특정 자세에서만** 문제를 일으킨다.
  전 작업공간 샘플링으로 검증한다.
- 접촉이 개입하면 위치 제어만으로 부족하다 — 임피던스/힘 제어 설계가 필요.
- 관련: `robot-kinematics`, `motion-planning`, `manipulation-control`

## 모바일 매니퓰레이터
- **베이스와 팔의 협조**가 핵심 문제다. 따로 계획하면 팔이 닿지 않는 곳에 베이스가 선다.
  전체를 하나의 운동학 체인으로 보는 whole-body 접근을 검토한다.
- 베이스 위치 오차가 팔 끝단 오차로 증폭된다. **베이스 정지 후 재측위** 전략이 실무적으로 안정적이다.
- 이동 중 팔의 관성이 베이스 주행에 영향을 준다. 이동 자세(tucked pose)를 정의한다.

## 사족 보행
- **접촉이 이산적으로 바뀐다** — 발이 닿고 떨어질 때마다 동역학이 달라진다.
  연속 최적화만으로 다루기 어려워 RL 이나 접촉 스케줄 기반 MPC 를 쓴다.
- 지형 인지 여부가 알고리즘을 나눈다. 블라인드 보행(고유수용감각만)은 강건하지만 느리고,
  지형 인지는 빠르지만 인지 실패에 취약하다. **teacher-student 로 둘을 결합**하는 것이 표준.
- 넘어짐이 정상 범주다. 낙상 감지·보호·복귀를 알고리즘의 일부로 설계한다.
- 관련: `legged-rl`, `robot-kinematics`(부동베이스)

## 휴머노이드 / 이족
- 사족보다 **본질적으로 불안정**하다. 지지 다각형이 작아 ZMP/CoM 관리가 상시 문제다.
- 상체 자유도가 많아 whole-body control 이 필요하다. 계산 예산이 크게 든다.
- 부동베이스 동역학(`nq ≠ nv`, 쿼터니언)을 정확히 다뤄야 한다 — 여기서 조용한 버그가 많이 난다.
- 안전 설계가 가장 어렵다. 넘어질 때 사람·자신을 보호하는 동작이 별도 알고리즘이다.

## 다중 로봇
- 개별 최적이 전역 최적이 아니다. **교착을 알고리즘 설계 시점에 다룬다**
  (사후 처리로 풀리지 않는다).
- 통신 지연·손실을 가정에 넣는다. 모든 로봇이 같은 정보를 동시에 안다는 가정은 현장에서 깨진다.
- 확장성을 대수 기준으로 검증한다. 5대에서 되던 것이 30대에서 안 되는 일이 흔하다.
- 관련: `multi-robot-fleet`, `robot-networking`

## 학습 기반을 섞을 때 (공통)
- 학습 모듈의 **출력 범위를 하드 클램프**한다. 학습된 것은 언제든 이상한 값을 낸다.
- 학습 부분과 고전 부분의 **경계를 명확히** 한다. 어디까지가 보장되는 동작인지 말할 수 있어야 한다.
- 분포 밖 입력(OOD)을 감지해 안전 모드로 떨어지는 경로를 만든다.
- 관련: `deep-learning-vision`, `imitation-learning`, `vla-vlm-robotics`

## 논문을 구현할 때

- **재현 가능한지 먼저 확인**한다. 저자 코드가 있으면 그것부터 돌린다.
  없으면 재현 난이도를 높게 잡는다 (논문의 절반은 그대로 재현되지 않는다).
- 논문의 실험 조건(센서, 주파수, 환경)과 내 조건의 차이를 표로 적는다.
  차이가 크면 성능도 다를 것이라고 가정한다.
- 논문에 안 적힌 것들이 성능을 좌우한다: 초기화, 이상치 처리, 파라미터 스케줄, 전처리.
  이 부분에서 막히면 저자 코드나 이슈 트래커를 뒤진다.
- **논문 성능을 목표로 잡지 않는다.** 내 요구사항을 목표로 잡는다.
