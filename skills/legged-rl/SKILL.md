# 보행 강화학습 (Legged RL)

사족·이족 보행은 손으로 짜기 어렵고 RL 이 잘 통하는 대표 영역이다.
다만 **sim-to-real 이 성패의 90%** 다. 시뮬 성능은 거의 의미가 없다.

## 표준 파이프라인

```
1. 시뮬 환경 (Isaac Lab / MJX / MuJoCo Playground)  — 수천 환경 병렬
2. PPO 로 정책 학습                                  — 수 시간
3. 도메인 랜덤화 + 지형 커리큘럼                       — 여기가 sim2real 의 핵심
4. (선택) teacher-student 증류                       — 특권정보 → 실측 관측
5. ONNX/TorchScript export → 온보드 배포              — 제어 주기 고정
6. 실기 튜닝 및 안전 계층                             — 낙상 대비
```

## 관측 · 액션 설계

**관측 (실기에서 얻을 수 있는 것만)**
- 기본 자세: 중력 방향 벡터(base 프레임 투영) — 절대 자세보다 일반화가 좋다
- 기본 각속도 (IMU)
- 관절 위치·속도
- 이전 액션 (매우 중요 — 동작 연속성과 진동 억제)
- 명령(command): 목표 선속도 x/y, 목표 각속도 yaw
- (선택) 지형 스캔 — 실기에서 얻기 어려우면 teacher 전용으로

**절대 넣지 말 것**: 정확한 base 위치/속도(실기에서 없음), 접촉력 실측(대개 없음),
지면 마찰계수. 이런 특권 정보를 student 관측에 넣으면 시뮬에서만 되는 정책이 된다.

**액션**
- 관절 목표 위치를 내고 **PD 제어기가 토크로 변환**하는 구조가 표준.
  토크 직접 출력은 불안정하고 실기 이식이 어렵다.
- 액션 스케일과 기본 자세(default joint pos) 기준 오프셋으로 출력한다.
- PD 이득(kp/kd)은 시뮬과 실기가 **같아야 한다**. 다르면 정책이 완전히 다르게 동작한다.

## 보상 설계

보상 항이 많아지면 튜닝이 불가능해진다. **각 항의 기여도를 반드시 로깅한다.**

전형적 구성:
- **추종 보상 (+)**: 명령 선속도·각속도 추종. 지수 형태 `exp(-err²/σ)` 가 일반적
- **생존 (+)**: 넘어지지 않으면 매 스텝 소량
- **에너지/토크 (−)**: 토크 제곱, 관절 속도 — 이걸 빼면 정책이 발작적으로 떤다
- **액션 변화율 (−)**: 연속 액션 차이 — 진동 억제에 가장 효과적
- **자세 (−)**: 몸통 기울기, 높이 편차
- **접촉 (−/+)**: 발이 아닌 부위 접촉 페널티, 발 체공시간(air time) 보상 → 걸음걸이 형성
- **관절 한계 (−)**: 한계 근처 페널티

**흔한 실패**:
- 추종 보상만 크면 → 미끄러지듯 이동하거나 제자리 진동
- 생존 보상만 크면 → 가만히 서 있는 것이 최적이 됨
- 에너지 페널티가 크면 → 움직이지 않음
- air time 보상이 없으면 → 발을 끄는 보행(shuffling)

보상을 바꿀 때는 **한 항씩** 바꾸고 학습 곡선과 영상을 함께 본다.

## 도메인 랜덤화 — sim2real 의 실체

랜덤화 대상과 이유:

| 대상 | 왜 |
|---|---|
| 링크 질량·관성 (±) | 모델 오차, 페이로드 변화 |
| 마찰계수 | 지면 재질이 매번 다름 |
| PD 이득 | 모터 특성 편차·온도 |
| 액추에이터 지연 | **가장 자주 빠뜨리는 것.** 실기 제어 지연이 시뮬에 없으면 정책이 실기에서 발진한다 |
| 관측 노이즈·지연 | IMU/엔코더 노이즈 |
| 외란(push) | 밀림 회복 능력 |
| 지형 (경사, 계단, 요철) | 커리큘럼으로 난이도 점증 |

- **액추에이터 네트워크**: 실기 모터의 토크 응답을 데이터로 학습해 시뮬에 끼워 넣는 기법.
  단순 PD 모델보다 sim2real 갭을 크게 줄인다. 사족 보행에서 널리 쓰인다.
- 랜덤화 범위가 너무 넓으면 정책이 보수적이 되어 성능이 떨어진다. 좁으면 실기에서 무너진다.
  **실기 측정값을 중심으로 현실적인 범위**를 잡는다. 추측으로 범위를 넓히지 않는다.

## Teacher-Student (특권 학습)

1. **Teacher**: 지형 높이맵, 마찰, 외력 등 특권 정보를 관측에 넣고 학습 → 성능 높음
2. **Student**: 실기에서 얻을 수 있는 관측(고유수용감각 이력)만으로 teacher 를 모방
3. 배포는 student

지형 인지 보행처럼 실기 관측이 빈약한 경우에 사실상 필수 구조다.

## 배포

- 정책 추론 주기와 PD 제어 주기를 분리한다. 정책 50~100 Hz, 저수준 PD 는 1 kHz 급.
- **추론 지연을 고정**한다. 지터가 크면 학습 때와 다른 시스템이 된다.
  파이썬 GC, 동적 할당, 로깅을 제어 경로에서 제거한다.
- 초기 자세로 부드럽게 이동한 뒤 정책을 활성화한다. 갑자기 켜면 로봇이 튄다.
- **낙상 감지 + 즉시 정지** 경로를 정책과 독립적으로 둔다.
- 첫 실기 테스트는 반드시 **매달아 놓고(gantry/hoist)** 한다. 바닥에서 바로 시작하지 않는다.

## 실기 실패 진단

| 증상 | 원인 |
|---|---|
| 시뮬은 완벽, 실기에서 즉시 넘어짐 | PD 이득 불일치, 액추에이터 지연 미모델링, 관절 부호/순서 뒤바뀜 |
| 고주파 진동 | 지연 미모델링, 액션 변화율 페널티 부족, 관측 노이즈 |
| 특정 방향만 안 됨 | 학습 시 명령 분포 편향 |
| 시간이 지나면 무너짐 | 모터 발열로 특성 변화, 상태 추정 드리프트 |
| 이상한 걸음걸이 | 보상 착취 — 접촉/air time 항 재설계 |
| 경사·계단에서만 실패 | 지형 커리큘럼 부족 또는 지형 관측 부재 |

**관절 순서·부호 검증**은 배포 전 필수 체크다. 시뮬과 실기의 관절 인덱스 순서가 다르면
정책은 정상인데 로봇이 즉시 넘어진다. 관절 하나씩 명령을 보내 실제로 어느 관절이 움직이는지
눈으로 확인한다.
