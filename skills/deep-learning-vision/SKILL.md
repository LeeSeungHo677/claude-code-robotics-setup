# 로봇 인지를 위한 딥러닝 · 비전

로봇의 인지는 벤치마크 점수가 아니라 **현장에서 무너지지 않는 것**이 목표다.
mAP 2% 개선보다 실패 모드 하나를 없애는 것이 가치가 크다.

## 먼저: 딥러닝이 필요한가

| 작업 | 우선 검토 |
|---|---|
| 알려진 마커·태그 인식 | **AprilTag/ArUco** — 학습 불필요, 정확, 설명 가능 |
| 색·형상이 명확한 물체 | 고전 CV (색 분할, 윤곽, 템플릿 매칭) |
| 평면 검출, 바닥 제거 | RANSAC, 법선 기반 — 학습 불필요 |
| 정해진 부품의 정밀 정렬 | 고전 정합(ICP) + 초기 추정만 학습 |
| 미지 물체, 다양한 조명·배경 | **딥러닝** |
| 의미 이해 ("사람", "지게차") | **딥러닝** |

**고전 방법으로 되는 것을 딥러닝으로 하면** 데이터·학습·검증·배포 비용이 전부 발생하고
설명 가능성을 잃는다. 하이브리드(딥러닝으로 후보 검출 → 기하로 정밀화)가 실무 최적인 경우가 많다.

## 작업별 모델 선택 기준

| 작업 | 고려 사항 |
|---|---|
| 2D 검출 | 실시간이면 YOLO 계열. 정확도 우선이면 2-stage. 소형 물체는 입력 해상도가 지배적 |
| 세그멘테이션 | 인스턴스 vs 시맨틱을 구분. 파지에는 인스턴스가 필요 |
| 깊이 추정 | 단안 깊이는 **스케일이 모호**하다. 로봇에서는 스테레오/ToF/LiDAR 를 우선 |
| 6D 자세 추정 | CAD 가 있으면 렌더-비교 방식이 강함. 없으면 학습 기반 + ICP 정밀화 |
| 추적 | 검출 후 연관(SORT/ByteTrack 계열)이 실용적. 재식별이 필요하면 외형 특징 추가 |
| 포인트클라우드 | 복셀 기반(희소 컨볼루션) vs 점 기반. 실시간이면 복셀+희소가 유리 |

- **개방 어휘 모델**(텍스트로 클래스 지정)은 유연하지만 느리고 오탐이 있다.
  고정 클래스가 정해진 산업 현장에서는 전용 모델이 대개 낫다 (`vla-vlm-robotics` 스킬).

## 데이터가 성능을 결정한다

- **현장 데이터가 최우선**이다. 공개 데이터셋으로 학습한 모델은 현장 조명·배경·카메라에서 무너진다.
- 합성 데이터(Isaac Sim Replicator 등)로 양을 채우고 현장 데이터로 미세조정하는 조합이 실용적이다
  (`nvidia-isaac` 스킬).
- **증강은 도메인에 맞게** 고른다. 로봇 카메라가 뒤집히지 않는다면 상하 반전 증강은
  쓸모없거나 해롭다. 유효한 증강: 조명/색조 변화, 모션 블러, 노이즈, 부분 가림, 스케일.
- 클래스 불균형을 확인한다. 희귀하지만 중요한 클래스(사람, 지게차)가 적으면
  가중치·오버샘플링으로 보정한다.
- **분할은 에피소드/장면 단위로.** 같은 장면의 프레임이 train 과 test 에 섞이면
  성능이 크게 과대평가된다 (`robot-data-pipeline` 스킬).

## 평가 — 로봇 기준으로

- mAP 만 보지 않는다. 로봇에 실제로 중요한 것:
  - **미검출률(FN)**: 사람을 못 보는 것은 치명적. 오검출보다 훨씬 나쁘다
  - **거리별 성능**: 먼 거리 소형 물체 성능이 실제 정지 거리를 결정한다
  - **지연**: 검출이 100 ms 늦으면 1 m/s 로 10 cm 늦게 반응한다
  - **시간적 일관성**: 프레임마다 깜빡이는 검출은 하류 로직을 망가뜨린다
- 운영 임계(confidence threshold)를 **용도별로** 다르게 잡는다.
  안전 관련(사람 검출)은 재현율 우선, 작업 대상 선택은 정밀도 우선.
- 실패 사례를 유형별로 모아 **회귀 테스트 세트**를 만든다.
  모델을 바꿀 때마다 이 세트로 확인한다. 예전에 고친 실패가 다시 나오는 것을 막는다.

## 현장 도메인 시프트

가장 흔한 원인과 대응:

| 원인 | 대응 |
|---|---|
| 조명 변화 (주간/야간/역광) | 해당 조건 데이터 수집, 노출 고정, HDR |
| 카메라 교체·재장착 | 캘리브레이션 재수행, 내부 파라미터 변화 확인 |
| 배경·레이아웃 변경 | 현장 데이터 추가 수집 |
| 렌즈 오염 | **오염 감지 로직** — 선명도 지표 모니터링 |
| 계절·날씨 | 장기 데이터 수집 계획 |

- 모델 출력의 **신뢰도 분포를 모니터링**한다. 배포 후 평균 신뢰도가 떨어지면
  도메인 시프트가 일어나는 중이다. 성능 저하를 사고 나기 전에 알 수 있는 신호다.

## 하류 시스템과의 계약

- 인지 결과에 **불확실성을 함께 전달**한다. 검출 박스만 주고 신뢰도를 안 주면
  계획 계층이 판단할 수 없다.
- 3D 위치를 낼 때 **좌표계와 타임스탬프를 명시**한다.
  검출 결과가 어느 프레임 기준인지 모호하면 반드시 사고가 난다.
- 검출이 없을 때와 인지가 실패했을 때(카메라 이상, 추론 오류)를 **구분해서 보고**한다.
  "물체 없음" 과 "볼 수 없음" 은 로봇이 다르게 반응해야 한다.
- 인지 실패 시 안전한 기본 동작을 정의한다. 대개는 감속·정지다.

## 학습 실무

- 베이스라인을 먼저 만든다. 사전학습 모델 + 소량 파인튜닝으로 숫자를 확보한 뒤 개선한다.
- 실험을 기록한다 (설정, 데이터 버전, 결과). 기록 없는 실험은 반복된다.
- 과적합 확인: train/val 곡선. 로봇 데이터는 양이 적어 과적합이 쉽다.
- 재현성: 시드 고정, 환경 고정(컨테이너), 데이터 버전 고정.
- 모델 아티팩트에 **메타데이터를 붙인다**: 학습 데이터 버전, 입력 해상도, 정규화 파라미터,
  클래스 목록. 이게 없으면 몇 달 뒤 그 모델을 못 쓴다.

## 배포로 넘길 때

- 정밀도 변환(FP16/INT8) 후 **반드시 정확도를 재측정**한다 (`gpu-optimization` 스킬).
- 전처리(리사이즈 방식, 정규화 상수, 색 채널 순서 BGR/RGB)가 학습과 **완전히 동일**해야 한다.
  여기 불일치가 "학습은 잘 됐는데 배포하면 성능이 이상한" 문제의 1순위 원인이다.
- 추론 실패·타임아웃 시 동작을 정의한다.
- 모델 버전을 로그와 진단 토픽에 실어 발행한다. 현장에서 어느 모델이 도는지 알 수 있어야 한다.
