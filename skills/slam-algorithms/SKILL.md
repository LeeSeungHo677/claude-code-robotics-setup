# SLAM 알고리즘

## 구조를 먼저 나눈다

```
프론트엔드 : 스캔 정합 / 특징 추적 → 상대 자세 (odometry)
백엔드     : 팩터 그래프 최적화 → 전역 일관성
루프 클로저 : 재방문 인식 → 드리프트 보정
맵 관리    : 표현(점/복셀/서브맵/메시), 저장·로드, 갱신
```

문제가 생기면 **어느 단계인지 먼저 특정한다.**
"맵이 이상하다" 는 프론트엔드 드리프트일 수도, 루프 클로저 오검출일 수도 있고 처방이 정반대다.

## 알고리즘 선택

| 센서·상황 | 후보 |
|---|---|
| 3D LiDAR + IMU, 실시간, 넓은 실외 | **FAST-LIO2**, LIO-SAM, GLIM |
| 3D LiDAR 단독, 튜닝 최소화 | KISS-ICP (파라미터가 거의 없다는 게 강점) |
| 2D LiDAR, 실내 AMR | Cartographer, slam_toolbox |
| 카메라 단독 | ORB-SLAM 계열 (스케일 모호성 주의) |
| 카메라 + IMU | VINS 계열, OpenVINS — 스케일 관측 가능 |
| 다중 센서 융합·연구용 확장 | GLIM (팩터그래프 기반, 모듈성 높음) |

**선택 기준**: 센서 구성 → 실시간 요구 → 환경(구조적/비구조적) → 튜닝 인력.
논문 성능이 아니라 **내 센서·내 환경에서의 재현성**으로 고른다.

## 프론트엔드 (스캔 정합)

| 방법 | 특징 |
|---|---|
| ICP (point-to-point) | 단순, 초기값에 민감, 느림 |
| point-to-plane ICP | 평면이 많은 실내에서 훨씬 잘 수렴 |
| GICP / VGICP | 분포 기반, 강건. 실무 기본값으로 좋다 |
| NDT | 복셀 정규분포. 초기값에 덜 민감, 해상도 파라미터가 중요 |
| 특징 기반 (LOAM 계열) | 엣지/평면 특징 추출 → 빠름. 특징이 없는 환경에서 실패 |

- **초기 추정값(initial guess)이 성능을 지배한다.** IMU 예측이나 이전 속도를
  초기값으로 주면 수렴 속도와 정확도가 크게 개선된다.
- **디스큐(deskew)** 를 반드시 한다. 회전 중 LiDAR 한 스캔 내에서 로봇이 움직이므로
  포인트마다 타임스탬프로 보정해야 한다. 이걸 빼면 회전 시 맵이 뭉개진다.
- 다운샘플링 해상도가 정확도-속도 트레이드오프의 주 손잡이다.
- 실패 감지: 정합 잔차(fitness score)와 수렴 반복 횟수를 항상 모니터링하고,
  임계 초과 시 **실패로 처리**한다. 조용히 나쁜 자세를 내보내면 맵이 망가진다.

## 백엔드 (팩터 그래프)

- **GTSAM** (iSAM2 로 증분 최적화) 또는 **Ceres**, **g2o**.
  실시간 SLAM 이면 증분 최적화(iSAM2)가 사실상 필수다.
- 그래프 구성: 노드 = 자세(또는 자세+속도+바이어스), 엣지 = 팩터
  (odometry, IMU preintegration, loop closure, GPS, plane/prior).
- **IMU preintegration** 을 쓰면 고주파 IMU 를 매번 최적화에 넣지 않아도 된다.
  LiDAR-inertial 에서 표준 기법.
- **노이즈 모델이 결과를 지배한다.** 공분산을 대충 넣으면 최적화가 잘못된 방향으로 수렴한다.
  센서 스펙과 Allan variance 로 근거 있는 값을 쓴다 (`robot-calibration` 스킬).
- **로버스트 커널**(Huber, Cauchy, DCS/GNC)을 루프 클로저 팩터에 반드시 적용한다.
  오검출 루프 하나가 전체 맵을 찢는다.

## 루프 클로저

- 후보 탐지: 위치 기반(반경 내 과거 노드) + 기술자 기반(Scan Context, BoW, 학습 기반).
- **검증이 탐지보다 중요하다.** 후보를 정합해서 잔차가 충분히 낮을 때만 팩터를 추가한다.
  기하 검증 없이 추가하면 거짓 양성으로 맵이 붕괴한다.
- 복도·창고처럼 **반복 구조(perceptual aliasing)** 가 있는 환경이 최악의 조건이다.
  이런 곳에서는 기술자만으로 판단하지 말고 오도메트리 불확실성 범위 안으로 후보를 제한한다.
- 루프가 안 잡히는 문제: 후보 반경, 기술자 임계, 최소 시간 간격 조건을 확인한다.
  너무 엄격하면 영원히 안 잡힌다.

## 맵 관리

- 표현 선택: 포인트클라우드(정확, 무거움) / 복셀·옥트리(가벼움) / 서브맵(부분 갱신 가능) / 메시.
- **서브맵 구조**를 권장한다. 루프 클로저 후 전체를 다시 만들지 않고 서브맵 자세만 갱신하면 된다.
- 저장 포맷과 좌표계 규약을 문서화한다. 맵을 다시 로드했을 때 원점이 다르면
  이전 웨이포인트가 전부 무효가 된다 — 현장 운영에서 매우 자주 터지는 문제.
- 동적 물체(사람, 지게차)를 맵에 넣지 않는다. 제거하지 않으면 유령 장애물이 영구히 남는다.
  제거 기법: 레이캐스팅 기반 free-space carving, 다중 관측 일관성 검사.

## 평가 — 수치 없이 개선하지 않는다

- **evo** 툴로 ATE(절대 궤적 오차)·RPE(상대 자세 오차)를 측정한다.
  ATE 는 전역 일관성, RPE 는 국소 정확도를 본다. 둘은 다른 것을 말한다.
- 기준 진실(ground truth): 모션캡처, RTK-GPS, 또는 전측량된 마커.
  없으면 **최소한 시작=끝 지점 복귀 오차**라도 측정한다.
- 같은 rosbag 으로 **여러 번** 돌려 재현성을 확인한다.
  멀티스레드 SLAM 은 실행마다 결과가 다를 수 있다.
- 평가 스크립트를 만들어 두고 파라미터 변경 시마다 자동 실행한다.
  눈으로 맵을 보고 "좋아진 것 같다" 로 판단하지 않는다.

## 증상 → 원인

| 증상 | 원인 |
|---|---|
| 회전할 때 맵이 뭉개짐 | 디스큐 미적용, IMU-LiDAR 외부 파라미터/시간 오프셋 |
| 직선 복도에서 드리프트 | 구조 부족으로 정합 축퇴 — IMU/휠 오도메트리 융합 필요 |
| 같은 복도가 두 겹으로 그려짐 | 루프 클로저 미검출 |
| 맵이 갑자기 찢어짐 | 루프 클로저 오검출 — 로버스트 커널·검증 강화 |
| 시간이 지날수록 느려짐 | 그래프가 무한 증가 — 노드 희소화(keyframe), 마지널라이제이션 |
| 실외에서만 실패 | 반사·강우·먼지로 인한 이상치. 이상치 제거 필터 |
| 초기 몇 초에 발산 | IMU 바이어스 초기화 실패 — 정지 상태에서 시작하도록 |

## 새 알고리즘을 설계·구현할 때

일반적인 절차(베이스라인 → 설계 → 구현 → 검증 → 배포 판단)와 로봇 종류별 고려사항은
**`robot-algorithm-design` 스킬**에 정리돼 있다. 아래는 SLAM 에 특화된 부분이다.

- **먼저 기존 것을 베이스라인으로 세운다.** 내 데이터에서 FAST-LIO 나 KISS-ICP 를 돌려
  숫자를 확보한 뒤 개선을 시작한다. 베이스라인 없이 만든 것은 비교할 수 없다.
- 모듈 경계를 프론트엔드/백엔드/루프로 명확히 나눈다. 섞으면 어느 부분이 기여했는지 알 수 없다.
- 결정론적 재현이 가능하게 만든다 — 시드 고정, 스레드 수 고정 옵션.
  디버깅 불가능한 SLAM 은 개선도 불가능하다.
- 중간 산출물(정합 잔차, 그래프 크기, 루프 후보 수)을 전부 기록·발행한다.
  이 값들이 없으면 실패 원인을 추정만 하게 된다.
