# 레포 검토

**우리 코드 리뷰가 아니다.** 남이 만든 것을 **가져올지 말지** 판정한다.
결론은 항상 셋 중 하나다: **통째로 채택 / 아이디어만 추출 / 안 씀.**

## 먼저 — 별 개수를 보지 않는다

별은 "화제가 됐다" 이지 "유지된다" 가 아니다. 아래를 본다.

```bash
gh repo view <owner>/<repo> --json name,description,licenseInfo,pushedAt,stargazerCount,openIssues,archived
gh api repos/<owner>/<repo>/commits --jq '.[0:5][] | "\(.commit.author.date[:10]) \(.commit.message | split("\n")[0])"'
gh api repos/<owner>/<repo>/contributors --jq 'length'
```

| 신호 | 판단 |
|---|---|
| 마지막 커밋 6개월 초과 | 유지 안 됨으로 가정. 이슈를 올려도 답이 없다 |
| 기여자 1명 | 그 사람이 그만두면 끝난다. 포크 비용을 미리 계산한다 |
| 열린 이슈가 많고 답변이 없음 | 별 수와 무관하게 죽은 레포다 |
| `archived: true` | 읽기 전용. 아이디어 추출만 가능 |

## 라이선스 — 코드를 읽기 **전에** 확인한다

- **MIT / BSD / Apache-2.0** — 대체로 문제없음. Apache-2.0 은 특허 조항이 있어 오히려 안전
- **GPL / AGPL** — 제품에 링크하면 우리 코드 공개 의무가 생길 수 있다. **회사 납품물이면 먼저 확인받는다**
- **라이선스 없음** — 기본이 "권리 유보" 다. 쓰면 안 된다. 아이디어만 본다
- 로봇 SDK·드라이버는 **벤더 라이선스가 별도**인 경우가 많다. `LICENSE` 만 보지 말고 하위 디렉토리도 본다

## 실제로 쓸 만한가

- **의존성**: `pyproject.toml`/`package.xml`/`requirements.txt` 를 본다.
  ROS 배포판이 우리와 다르면(Humble 아님) 이식 비용이 든다
- **테스트가 있는가.** 없으면 우리가 고칠 때마다 무엇이 깨지는지 모른다
- **예제가 도는가.** README 예제가 현재 코드와 맞는지 확인한다. 어긋나 있으면 문서가 낡은 것이고,
  대개 코드도 낡았다
- **하드웨어 가정**: 특정 로봇·센서·GPU 를 전제하는가. 우리 노트북에는 외장 GPU 가 없다
- **실기에 붙는 코드인가.** 그렇다면 안전 계층(타임아웃·E-stop·명령 유효성)이 있는지 본다.
  없으면 그대로 쓰지 않는다 — `robot-safety-reviewer` 를 태운다

## 아이디어만 가져올 때

통째로 쓰지 않기로 했어도 대부분 **가져올 것이 있다.** 아래를 뽑는다.

- 우리가 안 쓰던 **인터페이스 설계**·상태 기계·에러 분류
- **평가 방식**·벤치마크 정의
- 빠지기 쉬운 함정을 코드에서 어떻게 막았는지 (경계 검사, 단위 변환, 좌표계 처리)
- 문서·프롬프트·체크리스트 같은 **비코드 자산** — 우리 스킬에 흡수할 수 있는지 본다

가져온 것은 **출처를 남긴다.** 6개월 뒤에 어디서 왔는지 모르면 갱신할 수 없다.

## 출력

```markdown
# <owner>/<repo>

한 줄: 무엇을 하는 것인가
판정: 통째로 채택 / 아이디어만 / 안 씀  — 이유 한 줄

## 상태
| 라이선스 | 마지막 커밋 | 기여자 | 아카이브 |

## 쓸 만한가
- 의존성·ROS 배포판 / 테스트 / 예제 동작 / 하드웨어 가정 / 안전 계층

## 가져올 것
- (아이디어·설계·비코드 자산, 각각 어디에 반영할지)

## 안 가져오는 이유
```

저장: `~/knowledge/repos/<owner>-<repo>.md`

## Gotchas

- **읽지 않은 코드를 평가하지 않는다.** README 만 봤으면 그렇게 적는다
- 클론해서 보는 편이 빠를 때가 많다. 단 **`~/knowledge` 안에 클론하지 않는다** — 거기는 문서 저장소다
- 우리 세팅(`~/.claude`)에 반영하려면 `setup-maintenance` 의 4항목 반입 게이트를 통과시킨다:
  실제로 쓸 것인가 / 기존 스킬 한 섹션이면 되는가 / 안정화됐는가 / 공식문서 베끼기 아닌가
- 벤치마크 수치가 README 에 있으면 **누가 언제 측정한 것인지** 확인한다. 대개 저자가 유리한 설정에서 잰 것이다
