# 모션 플래닝

## 계층을 먼저 나눈다

```
전역 경로 계획 (Global)   : 맵 전체, 느려도 됨, 최적성 중요
  ↓ 경로(path) = 기하학적 점열
궤적 생성 (Trajectory)    : 시간·속도·가속도 부여, 운동학/동역학 제약 반영
  ↓ 궤적(trajectory) = 시간이 붙은 상태열
지역 회피 (Local)         : 실시간, 동적 장애물, 추종
  ↓ 속도 명령
```

**path 와 trajectory 를 구분하지 않는 것이 초심자의 첫 실수다.**
A\* 가 만든 격자 경로를 그대로 로봇에 주면 각지고 실행 불가능하다.
시간 파라미터화가 반드시 사이에 들어간다.

## 전역 계획 알고리즘 선택

| 상황 | 알고리즘 |
|---|---|
| 2D 격자, 원형 풋프린트, 홀로노믹 | A\*, Dijkstra, Theta\*(경로가 덜 각짐) |
| 비홀로노믹(차동/아커만), 후진 필요, 비원형 풋프린트 | **Hybrid A\***, State Lattice |
| 고차원 (팔 6~7축 이상) | 샘플링 기반 — RRT-Connect(빠름), RRT\*/BIT\*(최적성) |
| 맵이 자주 바뀜, 재계획 빈번 | D\* Lite, LPA\* (증분 재계산) |
| 다중 질의(같은 맵에 여러 번) | PRM (로드맵 재사용) |

- **RRT 계열은 최적이 아니다.** RRT\* 는 시간이 무한대일 때만 최적으로 수렴한다.
  현실적 시간 제한에서는 후처리 스무딩(shortcut)이 필수다.
- RRT-Connect 는 빠르지만 경로가 지저분하다. "빠르게 찾고 → 다듬는다" 가 표준 전략.
- 샘플링 기반은 **좁은 통로(narrow passage)** 에 약하다. 계획이 자주 실패하면
  알고리즘 튜닝보다 충돌 모델의 여유(margin)를 확인한다.

## 궤적 생성 · 시간 파라미터화

경로에 시간을 입히는 단계. 여기서 속도·가속도·저크 한계를 반영한다.

| 방법 | 특징 |
|---|---|
| **TOPP-RA** | 경로를 유지하며 시간만 최적화. 관절 속도/가속도/토크 한계 반영. MoveIt 기본 중 하나 |
| **Ruckig** | 온라인 저크 제한 궤적 생성. 목표가 실시간으로 바뀌는 상황에 강함 |
| 5차 다항식 / minimum-jerk | 점대점 이동, 부드럽고 단순 |
| B-spline / Bezier | 경유점이 많고 연속성이 필요할 때 |
| S-curve (사다리꼴+저크) | 산업용 컨트롤러 표준, 예측 가능 |

- **저크(jerk)를 제한한다.** 가속도만 제한하면 기구에 충격이 가고 진동이 남는다.
  그리퍼가 물체를 놓치거나 카메라가 흔들리는 원인이 대부분 여기다.
- 시작·끝 속도를 0 으로 강제하지 않으면 궤적을 이어붙일 때 불연속이 생긴다.
  연속 동작이면 blending 을 설계한다.
- 실행 가능성 검증: 생성된 궤적을 **미분해서** 속도·가속도가 한계 안에 있는지 확인한다.
  플래너가 준다고 믿지 않는다.

## 지역 회피

| 방법 | 적합 |
|---|---|
| DWA | 차동구동, 가볍고 예측 가능, 튜닝 직관적 |
| MPPI | 샘플링 MPC, 동적 장애물·복잡 비용함수에 강함. CPU 소모 큼 |
| VO / RVO / ORCA | 다중 로봇·다중 보행자, 상호 회피 |
| Potential Field | 단순하지만 **지역 최소점**에 빠진다. 단독 사용 금지 |
| MPC | 모델이 있고 제약을 명시적으로 걸고 싶을 때. 계산 예산 필요 |

- 지역 회피는 **전역 경로를 대체하지 않는다.** 지역 계획만으로 미로를 빠져나가려 하면 갇힌다.
- 동적 장애물은 위치가 아니라 **속도**를 추정해야 의미가 있다. 정적 코스트맵에 사람을 찍으면
  로봇은 항상 한 발 늦는다.

## 최적화 기반 플래닝

- **CHOMP / STOMP / TrajOpt**: 초기 궤적을 받아 비용을 낮추는 방식.
  초기 궤적이 나쁘면 지역 최소에 빠진다 → 샘플링 플래너로 초기해를 만들고 최적화로 다듬는 조합이 견고하다.
- 비용 항: 충돌 여유, 부드러움, 경로 길이, 관절 한계, 자세 유지. **가중치 튜닝이 전부**다.
  가중치를 바꿀 때 하나씩 바꾸고 결과를 저장한다.
- 실시간 요구가 있으면 반복 횟수 상한과 타임아웃을 반드시 건다. 최적화는 시간을 무한히 쓴다.

## MoveIt 2 사용 시

- 파이프라인: `planner (OMPL/Pilz/CHOMP)` → `simplification` → `time parameterization` → `execution`.
  문제가 어느 단계인지 먼저 특정한다.
- **Planning Scene 이 실제 환경과 같은지** 항상 먼저 확인한다. 계획 실패의 다수는
  알고리즘이 아니라 씬에 유령 장애물이 있거나 옥토맵이 오래된 것이다.
- `allowed_planning_time` 을 늘리기 전에 왜 실패하는지 본다. 시간을 늘려서 되는 문제와
  애초에 해가 없는 문제는 다르다.
- 그리퍼로 물체를 잡으면 `attached_collision_object` 로 붙여야 한다.
  안 붙이면 물체를 든 채로 그 물체와 충돌한다고 판단하거나, 반대로 물체를 무시하고 부딪힌다.
- Cartesian path(`computeCartesianPath`)는 **완료 비율(fraction)** 을 반드시 확인한다.
  0.7 을 성공으로 취급하면 중간에서 멈추는 동작이 나온다.

## 성능이 안 나올 때

| 증상 | 확인 |
|---|---|
| 계획이 오래 걸림 | 충돌 검사 비용 — 충돌 메시가 과도하게 복잡한가 |
| 경로가 각짐 | 스무딩/시간 파라미터화 누락, Theta\* 나 Hybrid A\* 고려 |
| 코너를 자름 | 풋프린트가 실제보다 작게 설정됨 |
| 매번 다른 경로 | 샘플링 기반의 정상 동작 — 시드 고정 또는 최적화 단계 추가 |
| 실행 중 궤적 이탈 | 궤적이 동역학적으로 실행 불가 — 가속도/토크 한계 재확인 |
| 좁은 통로 실패 | 충돌 margin, 샘플링 편향(goal bias), 통로 전용 샘플러 |

## 검증

- 실기 전에 **시뮬레이션에서 같은 시나리오를 반복 실행**해 성공률을 센다.
  1회 성공은 근거가 아니다. 20회 중 몇 번인지가 근거다.
- 생성된 궤적은 실행 전에 항상 충돌 검사를 다시 한다 (plan 과 execute 사이에 환경이 바뀐다).
- 계획 실패 시 로봇이 무엇을 하는지 정의한다. 정지인가, 이전 경로 유지인가, 회복 동작인가.
  정의하지 않으면 현장에서 예측 불가능하게 움직인다.
