# VLA · VLM in Robotics

언어·시각을 입력으로 받아 로봇 액션을 내는 모델. **범용성은 높지만 지연과 정밀도가 대가**다.
태스크 전용 정책(ACT/Diffusion)이 충분하면 VLA 를 쓸 이유가 없다.

## VLA 를 쓸 이유가 있는가 — 먼저 판단

| 상황 | 권장 |
|---|---|
| 태스크가 고정, 정밀도·속도 중요 | **ACT / Diffusion Policy** (`imitation-learning` 스킬) |
| 태스크가 다양, 언어로 지시하고 싶음 | VLA |
| 처음 보는 물체·환경에 일반화 필요 | VLA (또는 VLM + 기존 스택 조합) |
| 온보드 GPU 가 빈약하다 | VLA 부적합 — 또는 서버 추론 + 로컬 안전계층 |

**현실적 대안**: VLM 은 *인지·계획*에만 쓰고 실행은 기존 모션 스택에 맡기는 하이브리드가
정밀도·안전성·디버깅 면에서 훨씬 다루기 쉽다.
예) VLM 이 "빨간 컵" 을 찾아 6D 포즈를 주면 → MoveIt 이 계획하고 실행.

## 주요 모델 지형

| 모델 | 특징 |
|---|---|
| **GO-1 / GO-2** (AgiBot) | ViLLA 듀얼 시스템. Action Expert 만 파인튜닝 가능. 가중치·데이터셋 모두 공개 |
| **OpenVLA** | 7B, 오픈소스. Prismatic VLM 을 Open X-Embodiment 로 파인튜닝. 커뮤니티 자료가 가장 많다 |
| **π0 / π0.5** (Physical Intelligence) | 흐름 매칭 기반, 적응성이 높다는 평가 |
| **GR00T N1.x** (NVIDIA) | 휴머노이드 대상. VLM 백본 + DiT 흐름매칭 정책, 고주파 액션 출력 |
| RT-2 계열 | 연구 계보상 중요, 접근성은 제한적 |

모델은 빠르게 바뀐다. **선택 전에 현재 시점 벤치마크와 라이선스를 직접 확인한다.**

### GPU 요구 (GO-1 기준, 2026-08 시점)

| 작업 | 최소 | 권장 |
|---|---|---|
| 추론 | RTX 4090 16GB | A100 40GB |
| LoRA 파인튜닝 | A100 40GB | A100 80GB |
| 풀 파인튜닝 | A100 80GB ×2 | A100 80GB ×4 |

이 노트북에는 외장 GPU 가 없다 — 학습·추론은 `cloud-gpu-job` 스킬(RunPod/Vast.ai)로 보낸다.

## 파인튜닝

- 대부분 **LoRA/어댑터**로 충분하다. 전체 파인튜닝은 비용 대비 이득이 작은 경우가 많다.
- 자기 로봇 데이터로 파인튜닝할 때 **액션 공간 정합**이 핵심이다.
  사전학습 모델의 액션 표현(정규화 범위, 좌표계, 그리퍼 인코딩)과
  내 로봇의 표현이 다르면 그럴듯하게 학습되지만 실기에서 엉뚱하게 움직인다.
- 데이터 요구량은 태스크 전용 정책보다 크다. 시연 수가 적으면 VLA 의 이점이 나오지 않는다.
- 언어 지시문을 **일관된 형식**으로 만든다. 같은 태스크를 매번 다르게 표현하면 학습이 흐려진다.
  단, 배포 시 표현 다양성이 필요하면 학습에도 다양성을 넣어야 한다.

## 추론 지연 — 가장 큰 실무 장벽

7B급 모델은 온보드에서 무겁다. 제어 주기를 맞추려면 다음을 조합한다.

- **액션 청킹**: 한 번 추론으로 여러 스텝을 얻어 추론 빈도를 낮춘다. 사실상 필수.
- **양자화**: bf16 → int8/int4. 정밀도 손실이 액션 품질에 미치는 영향을 반드시 측정한다.
- **TensorRT / 전용 런타임**으로 변환. 엣지 배포용 경량 VLA 런타임도 등장하고 있다.
- **비동기 구조**: 정책 추론과 제어 루프를 분리한다. 제어 루프는 항상 정해진 주기로 돌고,
  최신 액션 청크를 소비한다. 추론이 늦어도 제어가 멈추지 않아야 한다.
- **서버 추론**: 네트워크가 안정적이면 GPU 서버에서 추론. 단 네트워크 단절 시
  로봇이 무엇을 할지 반드시 정의한다.

## 안전 — VLA 는 예측 불가능하다고 가정한다

- 출력에 **하드 클램프**를 건다: 관절 한계, 속도 한계, 작업공간 경계, 힘 한계.
- 모델과 **독립된 안전 감시자**를 둔다. VLA 가 이상한 값을 내도 막을 수 있어야 한다.
  이 감시자는 학습 모델이 아니라 결정론적 규칙이어야 한다.
- 언어 입력은 신뢰 경계 밖이다. 사용자가 준 문장이 그대로 로봇 동작이 되는 구조에서
  무엇이 실행 가능한 명령인지 화이트리스트로 제한한다.
- 실기 실행 전 시뮬 또는 저속 모드에서 검증하는 단계를 파이프라인에 넣는다.

## VLM 을 인지에 쓸 때

- 개방 어휘 검출(open-vocabulary detection)·세그멘테이션으로 "빨간 상자" 같은 지시를 처리.
- **VLM 출력은 검증한다.** 환각이 있다. 검출 결과를 깊이·기하 제약으로 교차 검증하고,
  실패 시 "모르겠다"로 떨어지게 설계한다. 억지로 답을 만들면 로봇이 엉뚱한 곳을 집는다.
- 지연이 크므로 매 프레임 호출하지 않는다. 트리거 기반(작업 시작 시, 실패 시)으로 부른다.
- 좌표 변환: VLM 이 주는 이미지 좌표 → 3D 는 깊이·캘리브레이션이 정확해야 의미가 있다
  (`robot-calibration` 스킬).

## 평가

- 성공률뿐 아니라 **일반화 축**을 나눠 측정한다: 새 물체 / 새 배치 / 새 지시문 / 새 환경.
  하나만 좋아도 "일반화된다"고 말하지 않는다.
- 지연(p50/p99), 온보드 전력·발열, 장시간 안정성을 함께 기록한다.
  데모는 되는데 현장 8시간 운용이 안 되는 경우가 흔하다.
