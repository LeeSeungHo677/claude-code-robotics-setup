프로젝트 루트(또는 `design/`)에 둔다. **화면 코드보다 먼저** 쓰고, 화면을 고칠 때마다 이 파일부터 연다.
에이전트가 이 파일 없이 UI 를 만들기 시작하면 학습 분포의 평균이 나온다.

**쓰는 원칙**
- 형용사는 규칙으로 바꾼다. "깔끔하게" 는 아무 뜻이 없다 → "카드 테두리 없음, 묶음은 간격 24 로만".
- 금지값을 적는다. 모델은 금지만 있으면 가장 가까운 대체재로 가므로 **금지마다 대신 쓸 것**을 짝지어 적는다.
- 짧게. 한 장을 넘으면 `design/` 아래 주제별 파일로 나누고 여기서 가리킨다.
- 같은 회사 운영 화면은 **공통 DESIGN.md 하나**를 쓰고 제품별로 accent·로고만 덮어쓴다. 매번 새로 쓰지 않는다.

## 템플릿

```markdown
# DESIGN.md — <제품 이름>

## 방향 (우리 추가 — 코드 전에)
- 화면 종류: 운영·관제 / 제품·앱 / 랜딩·소개   ← SKILL.md 「만드는 절차」 0단계
- 주 업무 한 문장: <이 화면에서 사용자가 판단·하는 것>
- 주 행동 하나: <이 화면에서 가장 많이/중요하게 누르는 것>
- 사용 장면: <누가 · 어디서(조명·거리·장갑) · 얼마나 오래 · 어떤 기기>
- 안 쓰는 이유 / 지금 불편: <사용자가 이 화면을 피하거나 엑셀·터미널로 돌아가는 이유>
- 가진 재료: <실제 숫자·로그·로봇 사진·지도·스크린샷·고객 문구> — 차별화는 여기서 나온다.
  금지 목록과 스킬만 쓰면 결과는 다시 서로 닮는다(2026 영상 댓글 다수). 재료가 없으면 지어내지 말고 비워 둔다
- 형용사 4~5개 — 각각 이 제품에서 뜻하는 것 / 뜻하지 않는 것
  - 정밀한: 수치가 흔들리지 않고 단위가 분명 / 차갑고 무뚝뚝함이 아님
  - …
- 틀린 방향 (이렇게 되면 실패):
  - <예: SaaS 랜딩처럼 보임 — 가운데 hero, 카드 3장>
  - <예: 게임 HUD 처럼 보임 — 네온 glow, 각진 프레임 장식>
- 레퍼런스 (세 곳에서, 각각 무엇을 가져오나 — 값이 아니라 원리)
  - 실제 제품 (다른 산업): <이름> — <가져올 것: 표 밀도·정렬>
  - 인쇄·편집물·계기: <이름> — <가져올 것: 숫자 위계·skinny column>
  - 물리 세계: <이름> — <가져올 것: 산업 라벨의 색 규칙>
- 성격 한 줄 → 네 가지 결정이 여기서 나온다: <예: "공구함 — 각지고 좁고 낮은 채도, 짧은 명령형">
  - 서체 / 색 / radius / 문구 톤 — 각각 이 한 줄에서 왜 그렇게 되는지
- 세계(world): <이 제품이 속한 장소·재료 — 예: 야간 관제실의 계기, 공장 바닥의 안전 표지> → 무채색 온도와 accent 가 여기서 나온다
- 풍부한 곳(moments) 1~2개: <색·재질·디테일을 몰아줄 콘텐츠 — 예: 경로 지도, 그리퍼 단면도> — 나머지 chrome(탐색·버튼·테두리)은 조용히.
  꾸밈을 chrome 에 고루 뿌리면 템플릿이 되고, 콘텐츠 한두 곳에 모으면 기억에 남는다
- 서명(signature) 하나: <이 제품만의 작은 디테일, 일관되게 — 예: 환경 배너, 로봇 glyph, 키캡 단축키>. 다섯 개가 아니라 하나

## Colors
```yaml
inputs: { base: "oklch(L C H)", accent: "oklch(L C H)", contrast: normal }   # 입력 2~3개, 나머지는 생성
roles:
  bg: …        surface-1: …   surface-2: …   line: …
  text: …      text-dim: …    text-mute: …
  accent: …    accent-text: …
  ok: …        warn: …        err: …         info: …    # 색만으로 구분하지 않는다 — 모양·숫자·문구를 겹친다
```
- 금지: 프레임워크 기본 팔레트(indigo·violet), 장식 그라디언트 → 대신 accent 단색 하나
- light/dark 는 사용 장면으로 고른다: <예: 관제실 상시 → dark, 밝은 공장 태블릿 → light>

## Typography
- 본문: <family> — 왜 (폭·숫자 형태·한글 지원·실제 크기로 렌더해 본 결과)
- 수치·로그: <mono family> + tabular-nums slashed-zero
- 한글: <family> · word-break: keep-all · 본문 행간 1.6~1.7
- 스케일: <base>px × <ratio> — 콘텐츠 기준 치수 <예: 카메라 썸네일 높이 180>에서 나온 값 포함
- 금지: Inter/Roboto/system-ui 단독, 대문자+자간 라벨 → 대신 문장형 라벨

## Layout
- grid: 콘텐츠 치수에서 (<예: 표 최소 열 120 · 지도 패널 2/3>) — 12 등분으로 시작하지 않는다
- 간격 토큰: 4px 배수 <목록> · 위계: 묶음 안 < 묶음 사이 < 섹션 사이
- 밀도 모드: <compact 24 / regular 32 / touch 48 행 높이 중 무엇>

## Elevation & Depth
- 깊이 표현 하나: 선 / 그림자 (둘 다 쓰지 않는다). 그림자면 광원 하나·2~3겹·3단계 토큰

## Shapes
- radius 3단계: <sm/md/lg>. 겹친 표면은 바깥 = 안쪽 + 여백

## Motion
- <상태 전환 150~200ms ease-out 정도만 / 운영 화면은 데이터 갱신 모션 없음>

## Voice & Content
- 버튼 = 동사+목적어, 같은 동작은 끝까지 같은 이름
- 금지 단어 → 대신: "seamless·혁신적" → 제품 자신의 명사

## Components
- <대표 객체 컴포넌트(로봇 행·작업 카드…) 먼저. 상태 행렬은 SKILL.md §10>

## Do's and Don'ts
- Do: …
- Don't: … → 대신 …

## 운영·관제 화면이면

다른 화면과 같은 절차로 쓴다(형용사·레퍼런스·세계 포함). **반드시 채우는 것은 둘** — [operational-ui.md](operational-ui.md) 맨 위 「안전 최소선」.

- 환경 표시: 실기 / 시뮬 / 재생 — 이 컨셉에서의 생김새·위치
- 상태 등급표: 등급 · 색 · **색 말고 겹칠 단서**(모양·숫자·문구)

참고해서 필요하면 채운다: 화면 단계(개요 / 운영 / 상세 / 지원), stale 표시 방식(topic 별 timeout), 알람 예산 — 같은 문서의 참고 자료.

## 확인

- [ ] 금지마다 "대신" 이 있다
