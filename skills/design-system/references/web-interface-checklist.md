`design-system` 이 척도·토큰을 다룬다면, 이 목록은 **빠지면 사용자가 바로 불편을 겪는 동작 규칙**이다.
화면을 넘기기 전에 위에서부터 훑는다. 각 줄은 "있다/없다" 로 판정되게 썼다.

## 키보드 · 포커스

- [ ] 포커스 링이 보인다 — `:focus-visible` 로 (마우스 클릭엔 안 뜨게). 묶음은 `:focus-within`
- [ ] `outline: none` 을 썼다면 대체 표시가 있다
- [ ] sticky 헤더·고정 패널이 포커스된 요소를 가리지 않는다 (`scroll-margin-top`)
- [ ] 모달은 포커스를 가두고(trap), 닫으면 연 버튼으로 돌려준다
- [ ] 클릭으로 되는 것은 키보드로도 된다. 드래그 동작에는 클릭·키보드 대안이 있다
- [ ] `<div onclick>` 으로 이동하지 않는다 — 이동은 `<a href>` (새 탭·가운데 클릭 지원), 동작은 `<button>`

## 입력 · 폼

- [ ] 붙여넣기를 막지 않는다 (로봇 ID·시리얼·토큰은 거의 항상 붙여넣는다)
- [ ] 입력 중에는 막지 않고, 제출·blur 뒤 검증한다. 오류는 **필드 옆**에, 제출 시 첫 오류로 포커스
- [ ] 제출 버튼은 요청이 시작될 때까지 활성, 시작되면 비활성 + 스피너 + **원래 라벨 유지**
- [ ] `type`·`inputmode`·`autocomplete`·의미 있는 `name`. ID·코드 입력은 `spellcheck="false"`
- [ ] 값은 앞뒤 공백을 trim 한다
- [ ] 저장 안 한 변경이 있으면 이동 전에 경고한다
- [ ] 체크박스·라디오는 라벨까지 한 클릭 영역 (`<label>` 로 감싸기)
- [ ] 클릭 영역 ≥ 24px (터치 기기 ≥ 44px). 아이콘이 작으면 패딩으로 영역을 넓힌다

## 상태 · URL

- [ ] **필터·탭·페이지·펼친 패널이 URL 에 반영된다** (`history.replaceState` + `URLSearchParams`).
      "이 화면 봐 주세요" 하고 링크를 보내면 같은 화면이 열려야 한다
- [ ] 뒤로/앞으로가 스크롤 위치와 상태를 되돌린다
- [ ] `<title>` 이 현재 화면을 말한다 (탭 여러 개 띄우는 운영자)

## 피드백 · 파괴적 동작

- [ ] **파괴적 동작(삭제·초기화·정지·덮어쓰기)은 확인을 받거나 되돌리기 창(Undo)을 준다.**
      확인 문구에는 대상 이름을 넣는다 ("robot-03 의 수집 세션 12개 삭제")
- [ ] 실패하면 낙관적 갱신을 되돌리고 무엇이 실패했는지 말한다
- [ ] 토스트·인라인 검증 메시지는 `aria-live="polite"` 영역에 쓴다 (경보는 `assertive` 를 신중히)
- [ ] 후속 입력을 여는 메뉴 항목·로딩 문구는 `…` 문자 ("이름 바꾸기…", "불러오는 중…")
- [ ] 막다른 화면이 없다 — 빈/오류 상태에 다음 할 일이 있다
- [ ] 빈·적음·많음·오류 상태를 각각 설계했다. 스켈레톤은 실제 내용과 같은 크기

## 모션

- [ ] `prefers-reduced-motion` 에서 줄이거나 끈다
- [ ] **`transition: all` 금지** — 바뀌는 속성만 나열한다
- [ ] `transform`·`opacity` 만 애니메이션한다 (`top/left/width/height` 금지)
- [ ] 애니메이션은 중간에 끊을 수 있다(입력이 오면 따라간다)
- [ ] 무엇을 뺄지는 `design-system` §7 「빼는 기준」

## 레이아웃 · 내용

- [ ] **flex/grid 자식에 `min-width: 0`** — 없으면 긴 로봇 이름·경로가 말줄임 대신 레이아웃을 밀어낸다
- [ ] 긴 텍스트 처리: `text-overflow: ellipsis` / `-webkit-line-clamp` / `overflow-wrap: anywhere` (경로·해시)
- [ ] 빈 문자열·빈 배열에서 UI 가 깨지지 않는다. 아주 긴 값·한 글자 값으로도 본다
- [ ] 의도치 않은 스크롤바가 없다. 1440 · 768 · 390 폭에서 확인 (`design-system` §11)
- [ ] 측정은 JS 대신 flex/grid 로

## 숫자 · 날짜 · 언어

- [ ] 비교하는 숫자는 `font-variant-numeric: tabular-nums`
- [ ] **날짜·시간·숫자는 `Intl.DateTimeFormat` / `Intl.NumberFormat`** — 손으로 `toFixed`+문자열 붙이기 금지.
      시간대를 표시한다(현장·서버·UTC 가 섞이는 운영 화면)
- [ ] 값과 단위 사이 줄바꿈 금지: `10&nbsp;MB`, `30&nbsp;Hz`
- [ ] 로봇 ID·토픽 이름·코드에는 `translate="no"` (브라우저 자동 번역이 망가뜨린다)

## 접근성 이름 · 상태 표시

- [ ] 아이콘만 있는 버튼에 `aria-label`. 장식 아이콘은 `aria-hidden="true"`
- [ ] 상태를 색만으로 구분하지 않는다 — 색 + 아이콘/글자
- [ ] 네이티브 요소(`button` `a` `label` `table`)를 ARIA 보다 먼저 쓴다
- [ ] 제목은 `<h1>`~`<h6>` 위계를 지킨다
- [ ] 대비 기준을 지킨다. hover/active/focus 에서 대비가 **올라간다**
- [ ] 차트 팔레트는 색각 이상에서도 구분된다 (번들 스킬 `dataviz`)

## 다크 모드 · 테마

- [ ] 다크 테마면 `<html>` 에 `color-scheme: dark` (스크롤바·폼 컨트롤이 따라온다)
- [ ] `<meta name="theme-color">` 가 배경과 맞다
- [ ] 네이티브 `<select>` 에 `background-color`·`color` 를 명시 (Windows 에서 흰 바탕에 흰 글씨)

## 성능 (운영 콘솔에서 실제로 문제 되는 것)

- [ ] 50행 넘는 목록은 가상화하거나 페이지로 나눈다
- [ ] 레이아웃 읽기·쓰기를 묶는다 (실시간 갱신 루프 안에서 `offsetHeight` 읽고 쓰기 반복 금지)
- [ ] 변경 요청(POST/PATCH/DELETE)은 500 ms 안에 응답하거나 진행 표시를 한다
- [ ] 폰트는 로컬 번들 + `font-display: swap` (폐쇄망 — `design-system` §1)
