# 디자인 시스템

> **적용 범위**: 이 스킬은 **운영자 대시보드·관제 화면·내부 도구**를 담당한다.
> 연출이 필요한 **소개·랜딩·데모**는 `frontend-design` 쪽이고, genjutsu 플러그인을 켜 두었다면
> `genjutsu:cast`(모션·3D·인터랙션)와 `genjutsu:paint`(아트디렉션·디자인 시스템 파이프라인)도 그쪽이다.
> 관제 화면에서 두 계열이 부딪히면 **이 스킬이 우선한다** — 실시간 값을 읽는 화면에서
> 연출은 판독을 방해한다.

**"AI가 만든 것 같다"의 정체는 대개 미적 감각이 아니라 척도(scale)의 부재다.**
값을 그때그때 정하면 화면이 미묘하게 어긋나고, 사람은 그걸 "설계되지 않았다"고 읽는다.

## 먼저: 진단 — 이 중 몇 개에 해당하는가

실제 코드에서 이렇게 확인한다.

```bash
# 폰트 크기 종류
grep -o "font-size:[^;]*" *.html *.css | sort -u
# 간격
grep -oE "(padding|margin|gap):[^;]*" *.html *.css | sort -u
# 모서리
grep -o "border-radius:[^;]*" *.html *.css | sort -u
```

| 증상 | 판정 |
|---|---|
| font-size 값이 **7종 넘음** | ❌ 타이포 스케일 없음 — 가장 큰 원인 |
| 간격이 4의 배수가 아닌 값 혼재 (5, 9, 14…) | ❌ 리듬 없음 |
| border-radius 3종 이상 혼용 | ❌ 형태 언어 불일치 |
| `font-family: system-ui` / Inter / Roboto / Arial | ❌ 폰트를 **고르지 않음** |
| 실시간 숫자에 `tabular-nums` 없음 | ❌ 값 바뀔 때 덜컹거림 |
| accent 색과 warn 색의 색상값이 비슷 | ❌ 기능 충돌 |
| 대비 4.5:1 미만 텍스트 | ❌ 읽기 어려움 |
| 카드 제목이 대문자+자간, 작은 라벨에 monospace | ❌ 템플릿 tell — 「AI 대시보드 tell」 |

**3개 이상이면 미학이 아니라 시스템 문제다.** 색을 바꾸거나 그림자를 추가해도 해결되지 않는다.

## 왜 "AI 가 만든 것 같은가" — 메커니즘

**분포적 수렴(distributional convergence).** 모델은 학습 데이터에서 지배적인 패턴을
고확률 기본값으로 샘플링한다. 지시가 없으면 가장 흔한 것이 나온다 —
Inter/Roboto, 보라 그라디언트, 균등한 여백, 둥근 카드, 최소한의 모션.

**그래서 "예쁘게" 라는 지시로는 안 바뀐다.** 그렇다고 기본값의 반대(극단 굵기, 그라디언트 메시,
순차 등장)를 고르는 것도 또 하나의 기본값이다 — 지금은 그쪽이 AI 생성물의 표지다.
벗어나는 방법은 "어느 축을 비틀까" 가 아니라 **이 화면의 업무에서 출발한 결정**이다.

## 만드는 절차 — 맥락 → 계획 → 구현 → 렌더해서 자기 비평

1. **맥락을 정한다.** 누가 보나(운영자·현장 엔지니어·고객 시연), 이 화면에서 **무엇을 판단하나**
   ("지금 문제 있나?", "어느 로봇이 멈췄나?"), 얼마나 오래 보나(8시간 상시 / 가끔), 어디서 보나
   (현장 노트북·폐쇄망·밝은 공장 조명). 화면의 주 업무를 **한 문장**으로 쓴다.
2. **계획한다** — 코드 전에, 짧게.
   - 색: 이름 붙인 hex **4~6개**(표면 2~3단, 본문 텍스트, accent 하나). 상태색 ok/warn/err/info 는 의미가 고정이라 별도(§3)
   - 서체 역할: 본문 / 수치·로그(mono + `tabular-nums`) / (선택) 제목. family 는 1~2개
   - 와이어프레임: ASCII 로 1~2안. 정렬 방침, 첫 화면 어디서 "문제 있나" 를 읽는지
   - 상태: 상호작용 컴포넌트마다 상태 행렬(§10)을 채운다
3. **계획을 검토한다.** "비슷한 요청(다른 로봇·다른 회사 대시보드)에도 똑같이 했을까?"
   그렇다면 그 부분은 기본값이다 — 이 화면의 업무에서 나온 결정으로 바꾸고 **무엇을 왜 바꿨는지 적는다.**
   운영 콘솔에서 다르게 하는 목적은 개성이 아니라 판독성이다. 같은 회사 대시보드끼리는
   `tokens.css` 를 공유하는 게 맞다(§8) — 비교 대상은 "아무 SaaS 템플릿" 이다.
4. **구현한다.** 토큰 먼저(§8), 컴포넌트에 원시값 금지.
5. **렌더해서 자기 비평한다.** §11 렌더 확인 루프로 스크린샷을 찍고, 「AI 대시보드 tell」 표와
   대조하고, 장식 하나를 덜어낸다. 코드만 보고 "괜찮다" 고 판단하지 않는다.

> 운영 대시보드에서는 **모션과 장식 배경을 절제**한다. 개성은 서체 선택·색 4~6개의 정밀함·
> 정보 위계에서 나온다.

## 1. 타이포 — 여기가 8할이다

### 스케일을 먼저 정한다
비율 기반으로 6~8단계만 만들고 **그 밖의 값은 쓰지 않는다.**

```css
:root{
  --t-xs:  11px;   /* 캡션, 배지 */
  --t-sm:  12px;   /* 보조 라벨 */
  --t-md:  13px;   /* 본문 — 대시보드 기본 */
  --t-lg:  15px;   /* 강조 본문, 카드 제목 */
  --t-xl:  20px;   /* 섹션 제목 */
  --t-2xl: 28px;   /* 주요 수치 */
  --t-3xl: 40px;   /* 히어로 수치 (한 화면에 1~2개만) */
}
```

**대시보드 본문은 13~14px이다.** 18~20px로 쓰고 있으면 화면이 "확대된 것처럼" 보이고
정보 밀도가 죽는다. 글자가 작아서 안 보이는 문제는 **크기가 아니라 대비와 행간**으로 푼다.

### 행간 · 자간
```css
--lh-tight: 1.15;   /* 큰 수치, 헤드라인 */
--lh-base:  1.5;    /* 본문 */
--lh-loose: 1.7;    /* 로그, 코드 */
```
- 큰 글자일수록 행간을 좁힌다. 40px 텍스트에 1.5는 뜬다.
- 자간은 건드리지 않는다. **라벨을 대문자 + 자간으로 만들지 않는다** — 업스트림 `frontend-design` 이
  꼽는 대표 tell(ALL-CAPS eyebrow)이다. 라벨은 문장형(sentence case — 첫 글자만 대문자, 한글은 그대로)으로
  쓰고 위계는 크기와 색(`--text-dim`)으로 만든다.

### 폰트 선택 — "고르는 것" 자체가 신호다
`system-ui` 는 "결정하지 않았다"는 뜻이고 사람은 그걸 알아본다.

기술 대시보드에 잘 맞는 방향:
- **본문**: 중립적이되 개성이 있는 산세리프 — 좁은 폭(condensed)이면 정보 밀도에 유리
- **수치·로그**: 반드시 **고정폭(monospace)**. 이것만 바꿔도 인상이 크게 바뀐다
  — 단 mono 는 **값·ID·로그에만**. 작은 데이터 라벨·메타 문자열까지 mono 로 쓰면 그것도 tell 이다
- 본문과 수치 폰트를 **다르게** 쓰는 것이 기술 제품의 표준 문법이다

```css
--font-sans: "본문폰트", system-ui, sans-serif;   /* fallback 은 남기되 첫 항목을 지정한다 */
--font-mono: "고정폭폰트", ui-monospace, monospace;
```

폰트 파일은 **로컬에 포함**한다. 폐쇄망 현장에서 CDN 폰트는 로드되지 않는다
(`robot-networking`). 로드 실패 시 fallback으로 레이아웃이 깨지지 않는지 확인한다.

## 2. 간격 — 리듬

**4px 배수만 쓴다. 예외 없이.**

```css
--s-1: 4px;  --s-2: 8px;  --s-3: 12px; --s-4: 16px;
--s-5: 24px; --s-6: 32px; --s-7: 48px; --s-8: 64px;
```

- 5px, 9px, 14px 같은 값이 하나라도 있으면 그 요소만 미묘하게 어긋나 보인다.
- **관련 있는 것은 가깝게, 없는 것은 멀게.** 카드 안 요소 간격(8) < 카드 사이 간격(16)
  < 섹션 사이 간격(32). 이 위계가 없으면 모든 것이 같은 무게로 보인다.
- 카드 패딩은 하나로 통일한다. 카드마다 12/14/16이면 그리드가 흔들린다.

## 3. 색

### 역할로 정의한다
```css
/* 표면 — 어두울수록 뒤 */
--bg:        #0d1117;   /* 페이지 */
--surface-1: #161b22;   /* 카드 */
--surface-2: #21262d;   /* 카드 안 요소, 입력 */
--line:      #30363d;   /* 경계선 */

/* 텍스트 — 대비로 위계 */
--text:      #e6edf3;   /* 본문 */
--text-dim:  #8b949e;   /* 보조 (본문 대비 4.5:1 유지) */
--text-mute: #6e7681;   /* 비활성 */

/* 상태 — 의미 고정, 재사용 금지 */
--ok: … --warn: … --err: … --info: …
/* 액션 — 상태색과 색상(hue)이 겹치면 안 된다 */
--accent: …
```

### 흔한 충돌
**accent(액션)와 warn(경고)이 같은 계열이면** 사용자가 버튼과 경고를 구분하지 못한다.
색상환에서 **최소 60° 이상** 벌린다. 주황 accent를 쓴다면 warn은 노랑이 아니라 다른 축으로.

### 검증
- 본문 대비 **4.5:1**, 큰 글자 3:1 이상. 보조 텍스트도 4.5:1 을 목표로 한다
- **상태를 색만으로 구분하지 않는다** — 색 + 아이콘/패턴 + 텍스트
- 다크에서 채도 높은 색은 진동한다. 채도를 낮춘 변형을 따로 둔다
- 화면을 **회색조로 렌더링**해보고 위계가 유지되는지 본다. 이게 가장 빠른 검증이다

## 4. 형태 — radius · 경계 · 높이

```css
--r-sm: 4px;   /* 배지, 입력 */
--r-md: 8px;   /* 카드, 버튼 */
--r-lg: 12px;  /* 모달, 큰 패널 */
```
**3단계면 충분하다.** 8/10/12/14를 섞으면 형태 언어가 무너진다.
전체 성격을 하나로 정한다 — 각지게 갈지 둥글게 갈지. 섞지 않는다.

깊이 표현은 **하나만 고른다**:
- 경계선(border) 중심 — 기술 대시보드에 잘 맞고 다크 모드에서 안정적
- 그림자(shadow) 중심 — 밝은 배경에 맞음

둘을 동시에 쓰면 지저분해진다. 그림자를 쓴다면 3단계 이하.

## 5. 수치 표시 — 대시보드의 핵심

```css
.num { font-family: var(--font-mono); font-variant-numeric: tabular-nums; }
```

- **`tabular-nums` 는 선택이 아니다.** 없으면 실시간 값이 바뀔 때마다 폭이 변해 덜컹거린다.
  이 한 줄이 "잘 만든 대시보드" 인상의 큰 부분을 차지한다.
- 값과 단위의 크기를 분리한다: 값 `--t-2xl`, 단위 `--t-sm` + `--text-dim`.
  같은 크기로 붙이면 단위가 값처럼 읽힌다.
- **소수 자릿수를 고정**한다. `12.5 → 12.53 → 12.5` 로 흔들리면 안 된다.
- 숫자는 **우측 정렬**, 라벨은 좌측 정렬. 표에서 소수점이 세로로 맞아야 한다.
- 값이 없을 때 `0` 이 아니라 `—` 로 표시한다. 0과 "알 수 없음"은 다르다.
- 갱신 시 색이 번쩍이는 효과를 넣지 않는다. 계속 보는 화면에서는 피로하다.

## 6. 밀도

대시보드는 **정보 밀도가 품질**이다. 여백 미학은 랜딩 페이지의 것이다.

- 한 화면에 필요한 정보가 다 들어가되, 그룹 간 경계가 명확해야 한다.
- 스크롤 없이 "지금 문제 있는가"를 판단할 수 있어야 한다.
- 카드 제목은 작고 흐리게(`--t-sm`, `--text-dim`), **문장형 라벨**로("배터리 전압", "최근 오류"),
  대문자·자간·mono 없이. 내용은 크고 선명하게. 제목이 내용보다 눈에 띄면 위계가 뒤집힌 것이다.
- 라벨이 없어도 읽히면 라벨을 뺀다. 모든 카드 위에 붙은 작은 제목줄은 템플릿처럼 보인다.
- 큰 수치(`--t-3xl`)는 **한 화면에 1~2개만**. 전부 크면 아무것도 크지 않다.

---

## 7. 모션 — 절제

- 상태 전환은 **150~200ms**, `ease-out`. 이보다 길면 느리게 느껴진다.
- 데이터 갱신에 애니메이션을 넣지 않는다. 매초 움직이면 읽을 수 없다.
- 진행률 바 같은 연속 값만 부드럽게 (`transition: width .3s`).
- 장식적 애니메이션은 운영 화면에 넣지 않는다. 8시간 보는 사람에게 방해가 된다.
- `prefers-reduced-motion` 을 존중한다. `transition: all` 은 쓰지 않는다 — 바뀌는 속성만 나열한다.

모션은 **스스로를 변호해야 남는다.** "이미 있다", "예쁘다" 는 변호가 아니다.

| 질문 | 그렇다면 |
|---|---|
| 키보드로 여나? (단축키·커맨드 팔레트·포커스 이동·화살표 탐색) | **삭제** |
| 하루 100회 이상 보나? (탭 전환·사이드바·목록 행·앱 내 화면 전환) | **삭제** — 그 빈도에선 어떤 길이도 지연으로 읽힌다 |
| 기능 데이터인가? (차트·표·숫자) | **삭제** — 마운트·갱신마다 재생은 장식. 사용자 동작으로 값이 실제로 바뀔 때만 |
| 목적(피드백·공간 연속성·상태 표시·급변 완화·설명)을 말할 수 없나? | **삭제** (드문 첫 경험 — 빈 상태·완료 — 만 예외) |
| 하루 수십 회? (hover·자주 쓰는 토글) | **축소** — 색/opacity 만, ≤150 ms |
| 300 ms 미만에 끝나는 작업에 스피너·shimmer? | **삭제** — 깜빡임이 오류처럼 보인다 |
| 상시 보이는 요소의 무한 루프(pulse·glow·shimmer)? | 한 번만 또는 정지 상태로. 알람 표시는 `ui-ux-design` 알람 규칙을 따른다 |

**지우기 전에 의존성을 확인한다** — 찾아 바꾸기로 지우면 회귀가 난다.
- 시작 상태: `opacity: 0` 에서 출발하는 keyframe·reveal 클래스 → 애니메이션만 지우면 영원히 안 보인다. 시작 상태도 같이 지운다
- 애니메이션을 기다리는 코드: `animationend`·`transitionend` 리스너, 길이에 맞춘 `setTimeout` → 같이 지운다
- 퇴장 애니메이션이 늦추던 unmount, 애니메이션 콜백 안의 focus 이동 → 즉시 실행으로 옮긴다
- 레이아웃 애니메이션이 가리던 점프 → 지웠더니 점프가 보이면 되돌리고 레이아웃 문제로 따로 보고
- 애니메이션 클래스·길이를 기다리는 테스트·셀렉터 → 같이 고친다

전체 감사는 `/remove-animations` (Emil 스킬 — 선택 설치, README 「선택 설치」 표).

## 8. 토큰으로 구현

```css
:root{
  /* 위의 --t-*, --s-*, --r-*, 색 전부를 여기 한 곳에 */
}
```

- **컴포넌트에 원시값(raw value)을 쓰지 않는다.** `padding:14px` 이 아니라 `padding:var(--s-3)`.
- 토큰 파일을 **프로젝트 간 공유**한다. 로봇별 대시보드가 각자 다른 값을 쓰면
  같은 회사 제품으로 보이지 않는다. 공통 `tokens.css` 하나를 두고 로봇별로는
  accent 색 정도만 오버라이드한다.
- 단일 HTML 대시보드라도 `:root` 블록만 복사해 쓰면 된다. 빌드 도구가 필요 없다.

## 9. 적용 순서 (기존 화면 개선 시)

기능은 되는데 디자인이 아쉬운 화면을 고칠 때, **이 순서가 효과 대비 비용이 가장 좋다.**

1. **타이포 스케일 정리** — font-size를 7종 이하로 축소. 본문을 13~14px로. ← 효과 가장 큼
2. **간격 4px 배수로 통일**
3. **radius 3단계로 통일**
4. **폰트 지정** — 본문 + 고정폭. `system-ui` 탈출
5. **수치에 tabular-nums + 단위 분리**
6. **색 충돌 해소** (accent vs warn), 대비 검증
7. 토큰으로 추출해 공유
8. **렌더 확인 루프**(§11)로 폭·테마·회색조를 한 번에 보고, 「AI 대시보드 tell」 대조

각 단계마다 **스크린샷을 남겨 비교**한다. 1~3번만 해도 대부분 "설계된 것처럼" 바뀐다.

## 10. 컴포넌트 상태 행렬

상호작용 컴포넌트(버튼·입력·목록 행·탭·토글·타일)는 계획 단계에서 **아래 8칸을 채운다.**
해당 없으면 `—` 로 적는다. 빈칸으로 두면 구현 때 기본값(=아무것도 안 바뀜)이 들어간다.

| 상태 | 무엇이 바뀌나 (토큰으로) | 흔한 실수 |
|---|---|---|
| default | 기준 | — |
| hover | 배경 한 단계(`--surface-1`→`--surface-2`) 또는 텍스트 대비 ↑. `@media (hover: hover)` 안에 | scale·lift·그림자 키우기, 터치 기기에서 hover 가 붙어 있음 |
| focus-visible | 2px outline(`--accent`), offset 2px | `outline: none`, `:focus` 로 마우스 클릭에도 링 |
| active | 한 단계 더 어둡게/밝게 | 상태 없음 → 눌렸는지 모름 |
| disabled | `--text-mute` + `cursor: not-allowed` + **왜 안 되는지**(보조문·`title`) | `opacity: .5` 하나 → 대비 미달, 이유 없음 |
| loading | 라벨 유지 + 스피너, **폭 고정** | 라벨이 스피너로 바뀌어 폭이 흔들림 |
| error | `--err` 테두리 + 아이콘 + 문장 (색만 X) | 빨간 테두리만 |
| selected | accent 옅은 배경 + 표시(체크·굵기) + `aria-selected`/`aria-pressed` | hover 와 구분 안 됨 |

데이터 위젯은 여기에 **빈 / 오래됨(stale) / 부분 실패 / 연결 끊김**이 더 붙는다 — 정의는 `ui-ux-design`.
동작 규칙(포커스·파괴적 동작 확인·URL 상태·`aria-live`·`Intl`·`min-width: 0`)은
[`references/web-interface-checklist.md`](references/web-interface-checklist.md).

## 11. 렌더 확인 루프 — 코드가 아니라 화면을 본다

**폭 3 × 테마 2 × 회색조** 를 한 번에 찍고 본다. 한 장만 보고 끝내지 않는다.

| 축 | 값 | 무엇을 보나 |
|---|---|---|
| 폭 | 1440 · 768 · 390 | 1440: 기본 밀도·스크롤 없이 "문제 있나" 판단 / 768: 열 접힘 / 390: 가로 스크롤 없음, 긴 이름 말줄임 |
| 테마 | light · dark | 대비, 상태색이 양쪽에서 구분되는지. 다크 전용 화면이면 dark 만 |
| 회색조 | `filter: grayscale(1)` | 색을 빼도 위계·상태가 읽히는지 (§3) |

```python
# uv run --with "playwright==$(playwright --version | cut -d" " -f2)" python shots.py <url|file:///…/index.html> <out-dir>
# 버전 고정 필수: 그냥 --with playwright 는 최신판을 받아 설치된 브라우저 빌드와 안 맞는다 → "Executable doesn't exist"
import sys, pathlib
from playwright.sync_api import sync_playwright
url, out = sys.argv[1], pathlib.Path(sys.argv[2]); out.mkdir(parents=True, exist_ok=True)
with sync_playwright() as p:
    b = p.chromium.launch()
    for scheme in ("light", "dark"):
        for w in (1440, 768, 390):
            pg = b.new_page(viewport={"width": w, "height": 900}, color_scheme=scheme)
            pg.goto(url); pg.wait_for_load_state("networkidle")
            pg.screenshot(path=out / f"{w}-{scheme}.png", full_page=True)
            if scheme == "dark" or w == 1440:
                pg.add_style_tag(content="html{filter:grayscale(1)}")
                pg.screenshot(path=out / f"{w}-{scheme}-gray.png", full_page=True)
            pg.close()
    b.close()
```

찍은 뒤 스스로 묻는다: 비슷한 요청에도 똑같이 만들었을까? 「AI 대시보드 tell」 중 몇 개가 보이나?
덜어낼 장식 하나는 무엇인가? 브라우저 조작·클릭 흐름 확인은 `webapp-testing` 스킬(선택 설치).

## AI 대시보드 tell — 보이면 고친다

<!-- 출처: anthropics/skills frontend-design @41bbe19 의 calibration 목록(Apache-2.0)을 운영 대시보드 기준으로 재구성 -->

모두 어떤 화면엔 맞을 수 있다. 문제는 **고른 게 아니라 그냥 나온 것**일 때다.

| tell | 대신 |
|---|---|
| 모든 제목 위의 대문자 + 자간 eyebrow 라벨 | 문장형 제목 하나. 필요 없으면 빼기 (§6) |
| `A · B · C` 가운뎃점으로 이은 메타 문자열 | 라벨–값 쌍, 또는 표의 열 |
| `WORD — fragment` 식 라벨 (띄운 em dash) | 평범한 문장 라벨 |
| 작은 데이터 라벨·메타에 monospace | mono 는 값·ID·로그에만 (§1) |
| SaaS 카드 키트 — 전부 같은 둥근 카드, 위계 무관 같은 radius, 같은 `rgba(0,0,0,.1)` 그림자, 장식 그라디언트 | 묶음은 간격·선으로(§2·§4, 깊이 표현 하나). 카드는 실제로 묶을 것이 있을 때만 |
| 이유 없이 고른 tinted near-black(`#0B0B0B`, `#111`) | 표면 단계를 §3 토큰으로 의도해서 정한다 (다크 관제 화면 자체가 문제는 아니다) |
| 링크·버튼 텍스트 끝의 `→` | 동사로 무엇이 일어나는지 ("로그 열기") |
| 순서가 아닌데 `01 / 02 / 03` 번호 | 순서·단계일 때만 |
| 큰 숫자 + 작은 라벨 + 그라디언트 액센트 KPI 타일 줄 | 판단에 필요한 수치만, 큰 수치는 1~2개 (§6) |
| 섹션마다 fade-and-slide-up 등장, 모든 카드 hover 전환 | §7 빼는 기준 |
| 제목에서 한 단어만 색·굵기 강조 | 강조하지 않거나, 값 자체를 강조 |
| 카드 안에 카드 | 담는 층은 하나. 안쪽 묶음은 간격·구분선으로 |
| 아무도 측정하지 않은 추세 화살표·지어낸 수치·샘플 값이 실제 값처럼 보임 | 실제 값만. 없으면 `—`(§5)와 "데이터 없음" 상태 |
| 인사말 + 스탯 카드 4개로 시작하는 첫 화면 | 이 도구를 대표하는 객체(로봇 목록·세션 타임라인·작업 큐)가 첫 화면을 이끈다 |
| 목적지가 몇 개 없는데 습관적으로 단 사이드바 | 목적지 7개 이하면 상단 바. 탭·브레드크럼 같은 익숙한 패턴 |
| accent 를 장식·아이콘 타일에 씀 | accent 는 주 동작·현재 선택·상태에만 |
| 320~1920 폭 어딘가에서 가로 스크롤, `position: sticky; top: 0` 두 개가 겹침 | `overflow-x: clip`, 두 번째 sticky 는 첫 번째 높이만큼 아래 |
| "seamless·robust·차세대·혁신적" 같은 문구, Jane Doe·Acme 같은 자리표시 이름 | 무엇을 하는지 제품 자신의 명사로 |

아래 외부 스킬은 **이 배포판에 들어 있지 않다** — README 「선택 설치」 표를 보고 직접 설치했다면 쓴다.
