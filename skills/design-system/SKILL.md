# 디자인 시스템

> **적용 범위**: 웹·앱·플랫폼 **모든 UI 의 공통 절차**(방향 문서 → 토큰 → 시안 비교 → 렌더 비평 → lint)는 이 스킬이다.
> 운영자 대시보드·관제 화면·내부 도구도 같은 절차(3a 컨셉 펼치기 포함)를 쓴다. 꼭 지킬 것은 **안전 최소선 2개**뿐이고
> ([`references/operational-ui.md`](references/operational-ui.md) 맨 위), 나머지 관제 관례는 같은 문서의 참고 자료다.
> 연출이 필요한 **소개·랜딩·데모**의 미학은 `frontend-design` 이 주도하고(절차·lint 는 여기를 따른다), genjutsu 플러그인을
> 켜 두었다면 `genjutsu:cast`·`genjutsu:paint` 도 그쪽이다.
> 관제 화면에 연출을 써도 된다 — 다만 실시간 값의 판독을 가리면 그 부분은 판독이 이긴다.

**"AI가 만든 것 같다"의 정체는 대개 미적 감각이 아니라 척도(scale)의 부재다.**
값을 그때그때 정하면 화면이 미묘하게 어긋나고, 사람은 그걸 "설계되지 않았다"고 읽는다.

## 먼저: 진단 — 이 중 몇 개에 해당하는가

실제 코드에서 이렇게 확인한다 — 「AI 대시보드 tell」 표와 척도(폰트 크기·간격·radius 종류 수)를 결정적으로 검사한다.

```bash
python3 ~/.claude/skills/design-system/scripts/design_lint.py <파일|디렉터리>   # --json, --strict
```

fail(그라디언트 글자·프레임워크 기본 보라·emoji 아이콘·`transition: all`)은 고친다. warn 은 고르거나 이유를 남긴다 —
같은 줄/윗줄에 `/* design-lint: allow <rule> — 이유 */`. 대비·accent 면적·가로 스크롤처럼 **렌더해야 아는 것은 못 본다** → §11.

| 증상 | 판정 |
|---|---|
| font-size 값이 **7종 넘음** | ❌ 타이포 스케일 없음 — 가장 큰 원인 |
| 간격이 4의 배수가 아닌 값 혼재 (5, 9, 14…) | ❌ 리듬 없음 |
| border-radius 3종 이상 혼용 | ❌ 형태 언어 불일치 |
| `font-family: system-ui` / Inter / Roboto / Arial | ❌ 폰트를 **고르지 않음** |
| `indigo-500`·`violet-600` 류 프레임워크 기본 팔레트, shadcn `:root` 토큰 그대로 | ❌ 색을 **고르지 않음** — 웹에서 가장 많이 지목되는 tell |
| 한글 화면인데 `word-break: keep-all` 없음 | ❌ 단어 중간 줄바꿈 (§1 한글) |
| 실시간 숫자에 `tabular-nums` 없음 | ❌ 값 바뀔 때 덜컹거림 |
| accent 색과 warn 색의 색상값이 비슷 | ❌ 기능 충돌 |
| 대비 4.5:1 미만 텍스트 | ❌ 읽기 어려움 |
| 카드 제목이 대문자+자간, 작은 라벨에 monospace | ❌ 템플릿 tell — 「AI 대시보드 tell」 |

**3개 이상이면 미학이 아니라 시스템 문제다.** 색을 바꾸거나 그림자를 추가해도 해결되지 않는다.

## 왜 "AI 가 만든 것 같은가" — 메커니즘

**분포적 수렴(distributional convergence).** 모델은 학습 데이터에서 지배적인 패턴을
고확률 기본값으로 샘플링한다. 지시가 없으면 가장 흔한 것이 나온다 —
Inter/Roboto, 보라 그라디언트, 균등한 여백, 둥근 카드, 최소한의 모션.

**그래서 "예쁘게" 라는 지시로는 안 바뀐다.** 그렇다고 기본값의 반대(극단 굵기, 그라디언트 메시,
순차 등장)를 고르는 것도 또 하나의 기본값이다 — 지금은 그쪽이 AI 생성물의 표지다.
"Inter 대신" 으로 흔히 처방되는 **Geist·Space Grotesk·Instrument Serif·Syne·Fraunces 도 이미 tell 로 집계된다**
(Krebs 2026, Show HN 사이트 DOM 감사). 처방이 다음 기본값이 된다.
벗어나는 방법은 "어느 축을 비틀까" 가 아니라 **이 화면의 업무에서 출발한 결정**이고,
상용 AI 도구들(v0·Figma Make·Stitch)도 같은 결론이다 — 모델이 잘 그려서가 아니라 **고를 수 있는 선택지를 좁혀서** 품질이 난다.

## 만드는 절차 — 단계를 건너뛰지 않는다

실무 디자이너와 상용 AI 도구가 공통으로 하는 것은 **방향 → 허용 값 → 여러 안 → 검사** 순서다.
우리 쪽 빈곳은 늘 앞 단계였다 — 고치는 장치(척도·tell 표·렌더 비평)는 있는데 **방향을 정하기 전에 코드부터 쓴다.**

**0. 화면 종류를 정한다.** 무엇을 건너뛸지가 여기서 정해진다.

| 종류 | 1 방향 | 3 시안 비교 | 품질의 기준 |
|---|---|---|---|
| 운영·관제·내부 도구 | 전부 (회사 공통 DESIGN.md 가 있으면 거기서 출발) | 2~3안 | 이 제품만의 성격 + 판독성 + 안전 최소선 2개 — [operational-ui.md](references/operational-ui.md) 맨 위, 관례는 참고 |
| 제품·앱·플랫폼 화면 | 전부 | 2~3안 | 이 제품만의 성격 + 판독성 |
| 랜딩·소개·데모 | 전부 | 2~3안 | `frontend-design` 미학 + 아래 검사 |

**1. 방향 문서 `DESIGN.md` 를 먼저 쓴다** — 템플릿 [references/design-md.md](references/design-md.md).
   - **시각 형용사보다 제품부터**: 주 업무 한 문장 · 주 행동 하나 · 사용 장면(누가·어디서·얼마나 오래·조명) ·
     지금 안 쓰는 이유 · **가진 재료**(실제 숫자·로그·로봇 사진·지도). 금지 목록만 지키면 결과는 다시 서로 닮는다 —
     차별화는 제품의 재료에서 나온다. 화면 목록·흐름은 `ui-ux-design` 으로 먼저 정하고, 스타일은 그 구조 위에 입힌다
   - 형용사 4~5개, 각각 **이 제품에서 뜻하는 것 / 뜻하지 않는 것**. **틀린 방향 목록**("SaaS 랜딩처럼 보이면 실패")
   - 레퍼런스를 **세 곳**에서 — 다른 산업의 실제 제품 · 인쇄물·계기·지도 · 물리 세계(산업 라벨, 키캡). 웹 갤러리만 보면 평균을 복제한다.
     각각 "무엇을 가져오나(원리)" 를 적는다. 값을 옮기지 않는다 — [reference-extraction.md](references/reference-extraction.md)
   - **성격 한 줄**에서 서체·색·radius·문구 톤 네 가지를 함께 도출한다. 따로 "무난하게" 고르면 합쳐서 템플릿이 된다.
   - 형용사는 관찰 가능한 규칙으로 바꾸고, 금지마다 **대신 쓸 것**을 짝짓는다 (Vercel design.md: 이렇게 바꾸자 알려진 결함 57% 감소, 6페이지 표본).

**2. 허용 값을 고정한다.** DESIGN.md → `tokens.css`(또는 Tailwind theme 교체). 이후 컴포넌트는 **토큰만** 쓴다(§8).
   색은 입력 2~3개에서 생성한다(§3). 팀 Figma 라이브러리가 있으면 그 변수·컴포넌트만 쓴다 — 없는 것을 지어내지 않는다.

**3. 펼친 뒤 좁힌다 — 사용자가 고른다** (모든 화면 종류 — 관제 화면은 첫 화면 대신 대표 화면 하나 크기로).

**3a 발산 — 컨셉 3개.** 서로 **세계·비유·레이아웃이 다른** 안을 첫 화면(hero + 대표 섹션 하나) 크기로 렌더해 나란히 보인다.
   - 한 안은 "누구나 떠올릴 안"(이 의뢰를 받으면 가장 먼저 나오는 것)으로 **하나만** 허용하고, 그렇다고 이름 붙인다.
     나머지 둘은 일부러 그 반대편에서 — 다른 세계(현장 재료·인쇄물·계기·지도…), 다른 구성(도면형·편집형·제품 사진형…)
   - 각 안에 한 줄: 세계 / 풍부한 곳 / 서명 / 이 안이 버린 것. 색만·폰트만 다른 셋은 발산이 아니다
   - 같은 모델은 같은 답으로 모인다(2026-11-26 A/B: 구·신 스킬 모두 "치수 도면 + 슬라이더" 로 수렴). 외부 생성 도구(Stitch EXPLORE/REIMAGINE)로
     안 하나를 받아 섞어도 된다 — 단 Stitch 변형은 색·톤만 넓고 레이아웃은 같았고 사양을 지어낸다. 숫자·고유명사는 사실표와 대조하고
     결과는 우리 토큰·lint 로 다시 만든다 ([reference-extraction.md](references/reference-extraction.md) §5)
   - Figma 를 쓰면 세 안을 한 페이지에 나란히 올려 사용자가 거기서 고르고 메모한다 (같은 문서 §4)

**3b 수렴 — 고른 컨셉 안에서 style tile 2~3개.**
   - 전체 화면이 아니라 **한 장짜리 조각 모음**: 서체 조합, 색, 버튼·입력·표 행·상태 배지·차트 한 조각, 실제 문구
   - 안끼리 **한 축만** 다르게(서체 / 색 온도 / 밀도 중 하나) — 무엇이 달라서 고르는지 보이게
   - 고른 뒤 여러 안의 좋은 부분을 오려 붙이지 않는다(Franken-comp)

   근거: 서로 다른 안을 병렬로 만든 쪽이 결과가 더 좋고 더 다양했다 (Dow 외 2010, 통제 실험 33명). 하나를 계속 고치면 첫 기본값에 갇힌다.
   3b 만 하면 그 갇힘을 색 고르기로 바꿀 뿐이다.

**4. 대표 기능 하나부터 구현한다.** 사이드바·헤더(shell)가 아니라 이 제품을 대표하는 객체 — 로봇 행, 작업 타임라인, 경로 지도 —
   를 **실제 데이터·극단값**(긴 이름·0개·1000개·오류)으로 먼저 완성하고, 거기서 정한 밀도·색을 shell 로 넓힌다.
   상호작용 컴포넌트는 상태 행렬(§10)을 채운다. 랜딩이면 hero 하나를 먼저 렌더·검토하고 섹션 단위로 넓힌다 — 한 번에 페이지 전체를 만들지 않는다.
   사람이 첫 화면을 Figma 에서 직접 고쳤다면 그 화면이 이후 화면의 기준이다 ([reference-extraction.md](references/reference-extraction.md) §4).

**5. 렌더 → 비평 → lint.** §11 렌더 루프로 찍고 본다. 중요한 화면은 **계획을 모르는 서브에이전트**에게 스크린샷과
   DESIGN.md 만 주고 「AI 대시보드 tell」·"관련 없는 제품이 이걸 그대로 써도 되나?" 로 판정시킨다.
   **lint 결과는 판단을 내린 뒤에 합친다**(먼저 보면 거기에 끌려간다). 마지막에 장식 하나를 덜어낸다.
   남긴 tell 은 고른 것이면 `design-lint: allow` 주석에 이유를 적는다.

> 코드만 보고 "괜찮다" 고 판단하지 않는다. "비슷한 요청(다른 회사·다른 제품)에도 똑같이 했을까?" 그렇다면 기본값이다.
> 대시보드·데이터 플랫폼도 개성을 낸다 — 단 실시간 값을 읽는 자리에서는 판독성이 이긴다. 같은 회사 화면끼리는 `tokens.css` 를 공유한다(§8).

## 1. 타이포 — 여기가 8할이다

### 스케일을 먼저 정한다
비율 기반으로 6~8단계만 만들고 **그 밖의 값은 쓰지 않는다.**

```css
:root{
  --t-xs:  11px;   /* 캡션, 배지 */
  --t-sm:  12px;   /* 보조 라벨 */
  --t-md:  13px;   /* 본문 — 대시보드 기본 */
  --t-lg:  15px;   /* 강조 본문, 카드 제목 */
  --t-xl:  20px;   /* 섹션 제목 */
  --t-2xl: 28px;   /* 주요 수치 */
  --t-3xl: 40px;   /* 히어로 수치 (한 화면에 1~2개만) */
}
```

**밀도 높은 대시보드 본문은 13~14px 가 출발점이다**(컨셉이 여유로운 쪽이면 키워도 된다). 이유 없이 18~20px로 쓰고 있으면 화면이 "확대된 것처럼" 보이고
정보 밀도가 죽는다. 글자가 작아서 안 보이는 문제는 **크기가 아니라 대비와 행간**으로 푼다.

### 행간 · 자간
```css
--lh-tight: 1.15;   /* 큰 수치, 헤드라인 */
--lh-base:  1.5;    /* 본문 */
--lh-loose: 1.7;    /* 로그, 코드 */
```
- 큰 글자일수록 행간을 좁힌다. 40px 텍스트에 1.5는 뜬다.
- 자간은 건드리지 않는다. **라벨을 대문자 + 자간으로 만들지 않는다** — 업스트림 `frontend-design` 이
  꼽는 대표 tell(ALL-CAPS eyebrow)이다. 라벨은 문장형(sentence case — 첫 글자만 대문자, 한글은 그대로)으로
  쓰고 위계는 크기와 색(`--text-dim`)으로 만든다.

### 폰트 선택 — "고르는 것" 자체가 신호다
`system-ui` 는 "결정하지 않았다"는 뜻이고 사람은 그걸 알아본다.

기술 대시보드에 잘 맞는 방향:
- **본문**: 중립적이되 개성이 있는 산세리프 — 좁은 폭(condensed)이면 정보 밀도에 유리
- **수치·로그**: 반드시 **고정폭(monospace)**. 이것만 바꿔도 인상이 크게 바뀐다
  — 단 mono 는 **값·ID·로그에만**. 작은 데이터 라벨·메타 문자열까지 mono 로 쓰면 그것도 tell 이다
- 본문과 수치 폰트를 **다르게** 쓰는 것이 기술 제품의 표준 문법이다

```css
--font-sans: "본문폰트", system-ui, sans-serif;   /* fallback 은 남기되 첫 항목을 지정한다 */
--font-mono: "고정폭폰트", ui-monospace, monospace;
```

**고르는 절차**: 본문 서체부터, 후보 2개를 **실제 크기(13~16px)·실제 문장·숫자·로그**로 렌더해 나란히 본다.
x-height·글자 구분(1/l/I, 0/O)·숫자 폭을 보고, 그 서체가 흔히 어디에 쓰이는지(문화적 연상)를 확인한다.
개성이 강한 서체는 제목 크기에만. 다양성은 family 수가 아니라 한 family 의 weight·폭에서 먼저 얻는다.
고른 이유를 DESIGN.md 에 한 줄로 남긴다 — 이유를 못 쓰면 고른 게 아니라 나온 것이다.

### 한글

- `word-break: keep-all; overflow-wrap: anywhere;` — 없으면 단어 중간에서 줄이 끊긴다(lint `hangul-break`). Tailwind 는 `break-keep`
- 한글 본문 행간은 라틴보다 넉넉하게(1.6~1.7). 제목은 1.3 안팎
- 한글 서체를 명시한다. 라틴 서체만 지정하면 한글은 OS 기본으로 떨어져 화면마다 달라진다.
  라틴·한글 짝을 정했으면 두 서체의 x-height·굵기가 섞여도 튀지 않는지 **실제 혼용 문장**으로 렌더해 본다
- 자리표시 문구(lorem, "텍스트")가 아니라 **실제 한글 문구**로 렌더해 검사한다 — 한글은 라틴보다 폭이 넓어 버튼·표 열이 넘친다

폰트 파일은 **로컬에 포함**한다. 폐쇄망 현장에서 CDN 폰트는 로드되지 않는다
(`robot-networking`). 로드 실패 시 fallback으로 레이아웃이 깨지지 않는지 확인한다.

## 2. 간격 — 리듬

**4px 배수만 쓴다. 예외 없이.**

```css
--s-1: 4px;  --s-2: 8px;  --s-3: 12px; --s-4: 16px;
--s-5: 24px; --s-6: 32px; --s-7: 48px; --s-8: 64px;
```

- 5px, 9px, 14px 같은 값이 하나라도 있으면 그 요소만 미묘하게 어긋나 보인다.
- **관련 있는 것은 가깝게, 없는 것은 멀게.** 카드 안 요소 간격(8) < 카드 사이 간격(16)
  < 섹션 사이 간격(32). 이 위계가 없으면 모든 것이 같은 무게로 보인다.
- 카드 패딩은 하나로 통일한다. 카드마다 12/14/16이면 그리드가 흔들린다.

## 3. 색

### 역할로 정의한다 — 값은 생성한다

<!-- 2026-11-26: 여기 있던 예시 hex 7개가 GitHub Primer dark 값 그대로였다 → 모델이 복사해 모든 대시보드가 "GitHub 다크" 가 됐다.
     값을 빼고 역할·생성 규칙만 남긴다. 예시 값을 다시 넣지 않는다. -->

```css
/* 역할 이름만 — 값은 아래 규칙으로 이 제품의 입력에서 만든다 */
--bg; --surface-1; --surface-2; --line;          /* 표면: 뒤 → 앞, 경계선 */
--text; --text-dim; --text-mute;                  /* 텍스트: 대비로 위계 (dim 도 본문 대비 4.5:1) */
--ok; --warn; --err; --info;                      /* 상태: 의미 고정, 재사용 금지 */
--accent; --accent-text;                          /* 액션: 상태색과 hue 가 겹치면 안 된다 */
```

**입력 2~3개에서 생성한다** (Linear: 변수 98개 → base·accent·contrast 3개, Stripe accessible color systems).
- 색공간은 **OKLCH**. 단계별 L(밝기)을 고정하면 hue 를 바꿔도 대비가 그대로다.
- **무채색도 색이다** — base 의 hue 와 아주 낮은 chroma(0.005~0.02)로 따뜻한/차가운 회색을 정한다. 순수 회색·남의 다크 테마 값을 쓰지 않는다.
- 램프(ramp) = 역할마다 한 단계. 아무 역할도 안 쓰는 단계는 만들지 않는다. 한 램프는 hue 를 끝까지 유지한다.
- 두 단 토큰: 원시(`--orange-600`, 컴포넌트에서 금지) → 의미(`--accent`, 컴포넌트는 이것만). 값이 지금 맞는다고 다른 역할 토큰을 빌려 쓰지 않는다.
- hue 15° 안은 같은 색으로 본다 — 한 색은 인터페이스 전체에서 한 가지 뜻.
- light / dark 는 **사용 장면**으로 고른다(관제실 상시 → dark, 밝은 공장 태블릿 → light). "기술 제품 = 다크" 는 tell 이다.
- Tailwind 는 `theme.colors` 를 **extend 가 아니라 교체**해 기본 팔레트가 아예 컴파일되지 않게 한다.
  shadcn 은 `:root` 토큰(색·radius)을 제품값으로 덮어쓴다 — 문제는 shadcn 이 아니라 토큰을 안 바꾼 것이다.

<!-- 출처: jakubkrehel/skills @672ae44 (MIT) better-colors — ramp·두 단 토큰·hue 15° 규칙 요약 -->

**accent 는 화면 면적의 5% 안팎**만 — 주 동작·현재 선택·상태. 넘치면 강조가 사라진다(§11 렌더에서 눈으로 확인).

### 흔한 충돌
**accent(액션)와 warn(경고)이 같은 계열이면** 사용자가 버튼과 경고를 구분하지 못한다.
색상환에서 **최소 60° 이상** 벌린다. 주황 accent를 쓴다면 warn은 노랑이 아니라 다른 축으로.

### 검증
- 본문 대비 **4.5:1**, 큰 글자 3:1 이상. 보조 텍스트도 4.5:1 을 목표로 한다
- **상태를 색만으로 구분하지 않는다** — 색 + 아이콘/패턴 + 텍스트
- 다크에서 채도 높은 색은 진동한다. 채도를 낮춘 변형을 따로 둔다
- 화면을 **회색조로 렌더링**해보고 위계가 유지되는지 본다. 이게 가장 빠른 검증이다

## 4. 형태 — radius · 경계 · 높이

```css
--r-sm: 4px;   /* 배지, 입력 */
--r-md: 8px;   /* 카드, 버튼 */
--r-lg: 12px;  /* 모달, 큰 패널 */
```
**3단계면 충분하다.** 8/10/12/14를 섞으면 형태 언어가 무너진다.
전체 성격을 하나로 정한다 — 각지게 갈지 둥글게 갈지. 섞지 않는다.

깊이 표현은 **하나만 고른다**:
- 경계선(border) 중심 — 기술 대시보드에 잘 맞고 다크 모드에서 안정적
- 그림자(shadow) 중심 — 밝은 배경에 맞음

둘을 동시에 쓰면 지저분해진다. 그림자를 쓴다면 3단계 이하 — **광원 하나**(모든 단계가 같은 x/y 비율),
alpha 낮춘 2~3겹, 배경 hue 로 살짝 물들임. `rgba(0,0,0,.1)` 한 겹은 SaaS 카드 키트의 표지다.

- **겹친 표면의 모서리**: 안쪽 요소가 고른 여백으로 들어 있으면 **바깥 radius = 안쪽 radius + 여백(+테두리)**.
  같은 radius 를 겹치면 모서리가 어색하게 뜬다. 여백이 24px 를 넘거나 비대칭이면 별개 표면으로 보고 각자 토큰을 쓴다.
- **아이콘 stroke 는 옆 글자 굵기에 맞춘다** — 400 에서 1.5px, 700 에서 2.5px 근처. 화면 하나에 아이콘 라이브러리 하나.
  SVG 안 `fill="#…"` 대신 `currentColor`.

<!-- 출처: jakubkrehel/skills @672ae44 (MIT) better-ui — concentric radius·icon stroke 요약 -->

이미 있는 화면을 다듬을 때의 순서: **빼기 → 플랫폼 기본값 → 기존 토큰 재사용 → 값 교정 → 추가**. 추가는 마지막이다.

## 5. 수치 표시 — 대시보드의 핵심

```css
.num { font-family: var(--font-mono); font-variant-numeric: tabular-nums slashed-zero; }
```
`slashed-zero` — 로봇 ID·시리얼·IP 에서 0/O 혼동이 엉뚱한 로봇 조작으로 이어진다. 폰트에 `zero` 대체 글자가 있는지 확인한다.
값 옆에는 목표·정상 범위·추세 중 판단에 필요한 것을 붙인다 — 운영 화면에서 참고할 관례는 [operational-ui.md](references/operational-ui.md) §2.

- **`tabular-nums` 는 선택이 아니다.** 없으면 실시간 값이 바뀔 때마다 폭이 변해 덜컹거린다.
  이 한 줄이 "잘 만든 대시보드" 인상의 큰 부분을 차지한다.
- 값과 단위의 크기를 분리한다: 값 `--t-2xl`, 단위 `--t-sm` + `--text-dim`.
  같은 크기로 붙이면 단위가 값처럼 읽힌다.
- **소수 자릿수를 고정**한다. `12.5 → 12.53 → 12.5` 로 흔들리면 안 된다.
- 숫자는 **우측 정렬**, 라벨은 좌측 정렬. 표에서 소수점이 세로로 맞아야 한다.
- 값이 없을 때 `0` 이 아니라 `—` 로 표시한다. 0과 "알 수 없음"은 다르다.
- 갱신 시 색이 번쩍이는 효과를 넣지 않는다. 계속 보는 화면에서는 피로하다.

## 6. 밀도

오래 들여다보는 대시보드는 **정보 밀도**가 품질을 크게 좌우한다 — 여백을 넓게 쓰는 컨셉도 가능하지만, 그때도 한 화면에서 판단에 필요한 것이 다 보여야 한다.

- 한 화면에 필요한 정보가 다 들어가되, 그룹 간 경계가 명확해야 한다.
- 스크롤 없이 "지금 문제 있는가"를 판단할 수 있어야 한다.
- 카드 제목은 작고 흐리게(`--t-sm`, `--text-dim`), **문장형 라벨**로("배터리 전압", "최근 오류"),
  대문자·자간·mono 없이. 내용은 크고 선명하게. 제목이 내용보다 눈에 띄면 위계가 뒤집힌 것이다.
- 라벨이 없어도 읽히면 라벨을 뺀다. 모든 카드 위에 붙은 작은 제목줄은 템플릿처럼 보인다.
- 큰 수치(`--t-3xl`)는 **한 화면에 1~2개만**. 전부 크면 아무것도 크지 않다.

## 7. 모션 — 절제

- 상태 전환은 **150~200ms**, `ease-out`. 이보다 길면 느리게 느껴진다.
- 데이터 갱신에 애니메이션을 넣지 않는다. 매초 움직이면 읽을 수 없다.
- 진행률 바 같은 연속 값만 부드럽게 (`transition: width .3s`).
- 오래 띄워 두는 화면(관제 등)의 장식 애니메이션은 피로가 되기 쉽다 — 넣는다면 멈추는 수단을 둔다.
- `prefers-reduced-motion` 을 존중한다. `transition: all` 은 쓰지 않는다 — 바뀌는 속성만 나열한다.

### 빼는 기준 — 이미 들어간 모션을 정리할 때

<!-- 출처: emilkowalski/skills remove-animations @64eb3de (MIT, Copyright (c) 2026 Emil Kowalski) 의 Gate·Removal Hazards 요약 -->

모션은 **스스로를 변호해야 남는다.** "이미 있다", "예쁘다" 는 변호가 아니다.

| 질문 | 그렇다면 |
|---|---|
| 키보드로 여나? (단축키·커맨드 팔레트·포커스 이동·화살표 탐색) | **삭제** |
| 하루 100회 이상 보나? (탭 전환·사이드바·목록 행·앱 내 화면 전환) | **삭제** — 그 빈도에선 어떤 길이도 지연으로 읽힌다 |
| 기능 데이터인가? (차트·표·숫자) | **삭제** — 마운트·갱신마다 재생은 장식. 사용자 동작으로 값이 실제로 바뀔 때만 |
| 목적(피드백·공간 연속성·상태 표시·급변 완화·설명)을 말할 수 없나? | **삭제** (드문 첫 경험 — 빈 상태·완료 — 만 예외) |
| 하루 수십 회? (hover·자주 쓰는 토글) | **축소** — 색/opacity 만, ≤150 ms |
| 300 ms 미만에 끝나는 작업에 스피너·shimmer? | **삭제** — 깜빡임이 오류처럼 보인다 |
| 상시 보이는 요소의 무한 루프(pulse·glow·shimmer)? | 한 번만 또는 정지 상태로. 알람 표시는 `ui-ux-design` 알람 규칙을 따른다 |

**지우기 전에 의존성을 확인한다** — 찾아 바꾸기로 지우면 회귀가 난다.
- 시작 상태: `opacity: 0` 에서 출발하는 keyframe·reveal 클래스 → 애니메이션만 지우면 영원히 안 보인다. 시작 상태도 같이 지운다
- 애니메이션을 기다리는 코드: `animationend`·`transitionend` 리스너, 길이에 맞춘 `setTimeout` → 같이 지운다
- 퇴장 애니메이션이 늦추던 unmount, 애니메이션 콜백 안의 focus 이동 → 즉시 실행으로 옮긴다
- 레이아웃 애니메이션이 가리던 점프 → 지웠더니 점프가 보이면 되돌리고 레이아웃 문제로 따로 보고
- 애니메이션 클래스·길이를 기다리는 테스트·셀렉터 → 같이 고친다

전체 감사는 `/remove-animations` (Emil 스킬 — 선택 설치, README 「선택 설치」 표).

## 8. 토큰으로 구현

```css
:root{
  /* 위의 --t-*, --s-*, --r-*, 색 전부를 여기 한 곳에 */
}
```

- **컴포넌트에 원시값(raw value)을 쓰지 않는다.** `padding:14px` 이 아니라 `padding:var(--s-3)`.
- 토큰 파일을 **프로젝트 간 공유**한다. 로봇별 대시보드가 각자 다른 값을 쓰면
  같은 회사 제품으로 보이지 않는다. 공통 `tokens.css` 하나를 두고 로봇별로는
  accent 색 정도만 오버라이드한다.
- 단일 HTML 대시보드라도 `:root` 블록만 복사해 쓰면 된다. 빌드 도구가 필요 없다.
- **브라우저 표면도 토큰에 넣는다** — 모델이 가장 확실히 빼먹는 곳이고, 다크 화면의 흰 스크롤바는 미완성 신호다:
  `color-scheme: light dark;`(스크롤바·폼 컨트롤) · `accent-color: var(--accent);`(체크박스·라디오) ·
  `::selection{background: …}` · `scrollbar-color` · `caret-color`.

## 9. 적용 순서 (기존 화면 개선 시)

기능은 되는데 디자인이 아쉬운 화면을 고칠 때, **이 순서가 효과 대비 비용이 가장 좋다.**

0. **`design_lint.py` 로 현황을 세고, 얼마나 바꿀지 먼저 정한다.**
   - 많다(색·타입·아이콘·문구 전반) → 아래 전체 + 「만드는 절차」 1단계 방향부터
   - 적다(대체로 설계된 화면) → **polish**: 기존 브랜드·팔레트·레이아웃 유지, 찾은 항목만. 큰 아이디어는 제안으로만
   - 없다 → 그렇다고 말하고 정확한 값으로 2~3개만 제안. **좋은 화면을 다르게 만들려고 바꾸지 않는다**
   - 방향을 새로 정하면 **찾은 것 목록 + 방향을 보여주고 사용자 답을 기다린 뒤** 고친다 — 방향을 나중에 바꾸면 전부 다시 한다
   fail 부터 고치고, 고친 뒤 다시 돌려 숫자로 비교한다.
   **보존 목록도 먼저 적는다** — 링크·폼 필드·버튼 동작(handler)·제목·단축키. 다듬은 뒤 하나라도 사라지면 실패다.
   운영 도구면 위치·용어도 보존 대상 ([operational-ui.md](references/operational-ui.md) §7)
1. **타이포 스케일 정리** — font-size를 7종 이하로 축소. 본문을 13~14px로. ← 효과 가장 큼.
   문구를 바꿀 거면 **문구 먼저** 확정한다 — 제목 길이가 크기와 자리를 정한다
2. **간격 4px 배수로 통일**
3. **radius 3단계로 통일**
4. **폰트 지정** — 본문 + 고정폭. `system-ui` 탈출
5. **수치에 tabular-nums + 단위 분리**
6. **색 충돌 해소** (accent vs warn), 대비 검증
7. 토큰으로 추출해 공유
8. **렌더 확인 루프**(§11)로 폭·테마·회색조를 한 번에 보고, 「AI 대시보드 tell」 대조

각 단계마다 **스크린샷을 남겨 비교**한다. 1~3번만 해도 대부분 "설계된 것처럼" 바뀐다.

## 10. 컴포넌트 상태 행렬

상호작용 컴포넌트(버튼·입력·목록 행·탭·토글·타일)는 계획 단계에서 **아래 8칸을 채운다.**
해당 없으면 `—` 로 적는다. 빈칸으로 두면 구현 때 기본값(=아무것도 안 바뀜)이 들어간다.

| 상태 | 무엇이 바뀌나 (토큰으로) | 흔한 실수 |
|---|---|---|
| default | 기준 | — |
| hover | 배경 한 단계(`--surface-1`→`--surface-2`) 또는 텍스트 대비 ↑. `@media (hover: hover)` 안에 | scale·lift·그림자 키우기, 터치 기기에서 hover 가 붙어 있음 |
| focus-visible | 2px outline(`--accent`), offset 2px | `outline: none`, `:focus` 로 마우스 클릭에도 링 |
| active | 한 단계 더 어둡게/밝게 | 상태 없음 → 눌렸는지 모름 |
| disabled | `--text-mute` + `cursor: not-allowed` + **왜 안 되는지**(보조문·`title`) | `opacity: .5` 하나 → 대비 미달, 이유 없음 |
| loading | 라벨 유지 + 스피너, **폭 고정** | 라벨이 스피너로 바뀌어 폭이 흔들림 |
| error | `--err` 테두리 + 아이콘 + 문장 (색만 X) | 빨간 테두리만 |
| selected | accent 옅은 배경 + 표시(체크·굵기) + `aria-selected`/`aria-pressed` | hover 와 구분 안 됨 |
| 권한 없음 | 조작을 숨기지 않고 비활성 + **누가 할 수 있는지**("관리자만 비상 정지 해제") | 버튼이 사라져 기능이 없는 줄 앎, 눌러 보고 나서야 403 |

데이터 위젯은 여기에 **빈 / 오래됨(stale) / 부분 실패 / 연결 끊김 / 권한 없음(보기 제한)**이 더 붙는다 — 정의는 `ui-ux-design`.
AI 는 **데이터가 꽉 찬 화면 하나만** 만드는 경향이 있다. 이 행들을 먼저 그린다.
동작 규칙(포커스·파괴적 동작 확인·URL 상태·`aria-live`·`Intl`·`min-width: 0`)은
[`references/web-interface-checklist.md`](references/web-interface-checklist.md).

## 11. 렌더 확인 루프 — 코드가 아니라 화면을 본다

**폭 3 × 테마 2 × 회색조** 를 한 번에 찍고 본다. 한 장만 보고 끝내지 않는다.
한 작업에서 **렌더 루프는 3번까지**다 — 매번 조금씩 고치며 찍기보다 찾은 것을 모아 한 번에 고친다.

| 축 | 값 | 무엇을 보나 |
|---|---|---|
| 폭 | 1440 · 768 · 390 | 1440: 기본 밀도·스크롤 없이 "문제 있나" 판단 / 768: 열 접힘 / 390: 가로 스크롤 없음, 긴 이름 말줄임 |
| 테마 | light · dark | 대비, 상태색이 양쪽에서 구분되는지. 다크 전용 화면이면 dark 만 |
| 회색조 | `filter: grayscale(1)` | 색을 빼도 위계·상태가 읽히는지 (§3) |
| 흐리게 | `filter: blur(6px)` (squint 테스트) | 글자가 안 읽힐 때 덩어리만으로 무엇이 가장 중요해 보이나 — 주 업무와 맞나, accent 가 몇 군데서 튀나 |

```python
# uv run --with "playwright==$(playwright --version | cut -d" " -f2)" python shots.py <url|file:///…/index.html> <out-dir>
# 버전 고정 필수: 그냥 --with playwright 는 최신판을 받아 설치된 브라우저 빌드와 안 맞는다 → "Executable doesn't exist"
import sys, pathlib
from playwright.sync_api import sync_playwright
url, out = sys.argv[1], pathlib.Path(sys.argv[2]); out.mkdir(parents=True, exist_ok=True)
with sync_playwright() as p:
    b = p.chromium.launch()
    for scheme in ("light", "dark"):
        for w in (1440, 768, 390):
            pg = b.new_page(viewport={"width": w, "height": 900}, color_scheme=scheme)
            pg.goto(url); pg.wait_for_load_state("networkidle")
            pg.screenshot(path=out / f"{w}-{scheme}.png", full_page=True)
            if scheme == "dark" or w == 1440:
                pg.add_style_tag(content="html{filter:grayscale(1)}")
                pg.screenshot(path=out / f"{w}-{scheme}-gray.png", full_page=True)
            if w == 1440:
                pg.add_style_tag(content="html{filter:blur(6px)}")
                pg.screenshot(path=out / f"{w}-{scheme}-blur.png")
            pg.close()
    b.close()
```

찍은 뒤 스스로 묻는다: 비슷한 요청에도 똑같이 만들었을까? 「AI 대시보드 tell」 중 몇 개가 보이나?
덜어낼 장식 하나는 무엇인가? 브라우저 조작·클릭 흐름 확인은 `webapp-testing` 스킬(선택 설치).

## AI 대시보드 tell — 보이면 고친다

<!-- 출처: anthropics/skills frontend-design @41bbe19 의 calibration 목록(Apache-2.0)을 운영 대시보드 기준으로 재구성 -->

모두 어떤 화면엔 맞을 수 있다. 문제는 **고른 게 아니라 그냥 나온 것**일 때다.

| tell | 대신 |
|---|---|
| 모든 제목 위의 대문자 + 자간 eyebrow 라벨 | 문장형 제목 하나. 필요 없으면 빼기 (§6) |
| `A · B · C` 가운뎃점으로 이은 메타 문자열 | 라벨–값 쌍, 또는 표의 열 |
| `WORD — fragment` 식 라벨 (띄운 em dash) | 평범한 문장 라벨 |
| 작은 데이터 라벨·메타에 monospace | mono 는 값·ID·로그에만 (§1) |
| SaaS 카드 키트 — 전부 같은 둥근 카드, 위계 무관 같은 radius, 같은 `rgba(0,0,0,.1)` 그림자, 장식 그라디언트 | 묶음은 간격·선으로(§2·§4, 깊이 표현 하나). 카드는 실제로 묶을 것이 있을 때만 |
| 이유 없이 고른 tinted near-black(`#0B0B0B`, `#111`) | 표면 단계를 §3 토큰으로 의도해서 정한다 (다크 관제 화면 자체가 문제는 아니다) |
| 링크·버튼 텍스트 끝의 `→` | 동사로 무엇이 일어나는지 ("로그 열기") |
| 순서가 아닌데 `01 / 02 / 03` 번호 | 순서·단계일 때만 |
| 큰 숫자 + 작은 라벨 + 그라디언트 액센트 KPI 타일 줄 | 판단에 필요한 수치만, 큰 수치는 1~2개 (§6) |
| 섹션마다 fade-and-slide-up 등장, 모든 카드 hover 전환 | §7 빼는 기준 |
| 제목에서 한 단어만 색·굵기 강조 | 강조하지 않거나, 값 자체를 강조 |
| 카드 안에 카드 | 담는 층은 하나. 안쪽 묶음은 간격·구분선으로 |
| 아무도 측정하지 않은 추세 화살표·지어낸 수치·샘플 값이 실제 값처럼 보임 | 실제 값만. 없으면 `—`(§5)와 "데이터 없음" 상태 |
| 인사말 + 스탯 카드 4개로 시작하는 첫 화면 | 이 도구를 대표하는 객체(로봇 목록·세션 타임라인·작업 큐)가 첫 화면을 이끈다 |
| 목적지가 몇 개 없는데 습관적으로 단 사이드바 | 목적지 7개 이하면 상단 바. 탭·브레드크럼 같은 익숙한 패턴 |
| accent 를 장식·아이콘 타일에 씀 | accent 는 주 동작·현재 선택·상태에만 |
| 320~1920 폭 어딘가에서 가로 스크롤, `position: sticky; top: 0` 두 개가 겹침 | `overflow-x: clip`, 두 번째 sticky 는 첫 번째 높이만큼 아래 |
| "seamless·robust·차세대·혁신적" 같은 문구, Jane Doe·Acme 같은 자리표시 이름 | 무엇을 하는지 제품 자신의 명사로 |

| tell (lint 규칙) | 대신 |
|---|---|
| 보라·indigo 주색, 보라→파랑 그라디언트, `bg-indigo-500` (`framework-default-palette`) — 웹 독립 출처 10곳이 지목, 가장 흔함 | 제품 입력에서 생성한 accent 단색 하나(§3) |
| 글자에 그라디언트 `background-clip: text` (`gradient-text`) | 단색. 강조는 굵기·크기 |
| 둥근 카드 왼쪽/위쪽 색띠 `border-left: 4px solid` (`side-stripe`) — 알람 카드에 특히 잘 나온다 | 전체 테두리·옅은 tint·앞쪽 상태 모양+문장 |
| 색 번짐 그림자(glow), 상태점 halo (`glow-shadow`) | 그림자는 깊이만(offset+blur). 상태는 모양+문구 |
| 반투명 유리 패널 `backdrop-filter` (`glassmorphism`) | 불투명 표면 토큰. 지도 위 오버레이처럼 이유 있을 때 1곳 |
| emoji 를 아이콘으로, 카드 제목마다 아이콘 타일 (`emoji-icon`) | 아이콘은 동작·상태를 구분할 때만, 라이브러리 1개·stroke 1종(§4) |
| `rounded-2xl` + `shadow-lg` 를 모든 것에 (`oversized-radius`) | radius 3단계, 위계별로 다르게 |
| Inter 대신 고른 Geist·Space Grotesk·Instrument Serif·Syne·Fraunces (`ai-default-font`) | 제품 맥락에서 후보 2개를 렌더해 고르고 이유를 DESIGN.md 에(§1) |
| 항상 다크 + 회색 본문 | light/dark 는 사용 장면으로(§3). 색 배경 위 보조 텍스트는 회색 말고 그 hue 로 |
| 흐린 색 덩어리(blob) 배경 장식 (`blob-decor`) | 표면 토큰 단색. 제품 재료(실제 화면·사진)로 채운다 |
| 상태와 무관하게 깜빡이는 "LIVE" 점·pill (`infinite-motion`) | 실제 녹화·진행 중일 때만, ack 안 된 알람만 깜빡임 |
| hover 에 카드가 커지거나 떠오름 (`hover-scale`) | 배경·테두리 한 단계 변화 |
| Jane Doe·Acme·lorem, 지어낸 숫자·후기 (`placeholder-copy`) / seamless·차세대·혁신적 (`hype-copy`) | 실제 데이터. 없으면 `{{name}}` 처럼 비어 있음을 드러낸다 |
| 느낌표·인사 제목("환영합니다 👋") (`exclaim-copy`·`greeting-copy`), 비교 기준 없는 변화 "+12%", "무엇이든 검색하세요…" | 제목은 맥락 이름("11월 수집 현황"). 변화는 "지난주 대비 +12%". 라벨은 짧게("검색") |
| 같은 크기 카드가 나란히, 카드마다 미니 차트 | 차트에도 위계 — 주 차트 하나를 가장 크게, 나머지는 표·순위 목록처럼 다른 종류로 작게. 숫자 카드는 숫자·라벨·비교만 |

> 이 목록은 **업계 합의가 아니라 우리 판단**이다(예: 제품 디자이너가 만든 다른 공개 스킬은 Geist·hero gradient 를 허용한다).
> 제품이 의도해서 쓰면 DESIGN.md 에 이유를 쓰고 `design-lint: allow` 로 남긴다.
