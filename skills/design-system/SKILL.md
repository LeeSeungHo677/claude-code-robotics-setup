# 디자인 시스템

> **적용 범위**: 이 스킬은 **운영자 대시보드·관제 화면·내부 도구**를 담당한다.
> 연출이 필요한 **소개·랜딩·데모**는 `frontend-design` 쪽이고, 모션·3D·스크롤 연출용
> 스킬을 따로 설치했다면 그것도 그쪽이다.
> 관제 화면에서 두 계열이 부딪히면 **이 스킬이 우선한다** — 실시간 값을 읽는 화면에서
> 연출은 판독을 방해한다.

**"AI가 만든 것 같다"의 정체는 대개 미적 감각이 아니라 척도(scale)의 부재다.**
값을 그때그때 정하면 화면이 미묘하게 어긋나고, 사람은 그걸 "설계되지 않았다"고 읽는다.

## 먼저: 진단 — 이 중 몇 개에 해당하는가

실제 코드에서 이렇게 확인한다.

```bash
# 폰트 크기 종류
grep -o "font-size:[^;]*" *.html *.css | sort -u
# 간격
grep -oE "(padding|margin|gap):[^;]*" *.html *.css | sort -u
# 모서리
grep -o "border-radius:[^;]*" *.html *.css | sort -u
```

| 증상 | 판정 |
|---|---|
| font-size 값이 **7종 넘음** | ❌ 타이포 스케일 없음 — 가장 큰 원인 |
| 간격이 4의 배수가 아닌 값 혼재 (5, 9, 14…) | ❌ 리듬 없음 |
| border-radius 3종 이상 혼용 | ❌ 형태 언어 불일치 |
| `font-family: system-ui` / Inter / Roboto / Arial | ❌ 폰트를 **고르지 않음** |
| 실시간 숫자에 `tabular-nums` 없음 | ❌ 값 바뀔 때 덜컹거림 |
| accent 색과 warn 색의 색상값이 비슷 | ❌ 기능 충돌 |
| 대비 4.5:1 미만 텍스트 | ❌ 읽기 어려움 |

**3개 이상이면 미학이 아니라 시스템 문제다.** 색을 바꾸거나 그림자를 추가해도 해결되지 않는다.

## 왜 "AI 가 만든 것 같은가" — 메커니즘

**분포적 수렴(distributional convergence).** 모델은 학습 데이터에서 지배적인 패턴을
고확률 기본값으로 샘플링한다. 지시가 없으면 가장 흔한 것이 나온다 —
Inter/Roboto, 보라 그라디언트, 균등한 여백, 둥근 카드, 최소한의 모션.

**그래서 "예쁘게" 라는 지시로는 안 바뀐다.** 기본값에서 벗어나려면
**어떤 축에서 얼마나 벗어날지**를 명시해야 한다.

## 기본값에서 벗어나는 축 — 어중간하면 티가 난다

| 축 | 기본값(수렴) | 벗어나기 |
|---|---|---|
| 굵기 | 400 / 600 (1단계 차이) | **100·200 vs 800·900** — 두 극단만 쓰고 중간을 비운다 |
| 크기 | 1.5배 단계 | **3배 이상 점프** — 위계가 즉시 읽힌다 |
| 색 | 균등 분포 팔레트 | **지배색 하나 + 날카로운 액센트** |
| 배경 | 단색 | 그라디언트 메시·기하 패턴·미세 질감 |
| 모션 | 흩어진 마이크로 인터랙션 | **`animation-delay` 로 단계적 등장 한 번** |
| 서체 | system-ui / Inter | 성격 있는 서체를 **의도적으로** 고른다 |

**핵심은 "과하게" 가 아니라 "어중간하지 않게" 다.** 굵기를 300/600 으로 두면
대비가 있는 듯 없는 듯해서 오히려 설계 안 된 것으로 읽힌다.
극단을 쓰되 **그 극단을 일관되게** 쓰면 절제와 개성이 동시에 나온다.

> 단, 운영 대시보드에서는 **모션과 장식 배경을 절제**한다.
> 타이포 대비·크기 비율·지배색은 그대로 적용해도 좋다 — 그쪽은 밀도와 충돌하지 않는다.

## 1. 타이포 — 여기가 8할이다

### 스케일을 먼저 정한다
비율 기반으로 6~8단계만 만들고 **그 밖의 값은 쓰지 않는다.**

```css
:root{
  --t-xs:  11px;   /* 캡션, 배지 */
  --t-sm:  12px;   /* 보조 라벨 */
  --t-md:  13px;   /* 본문 — 대시보드 기본 */
  --t-lg:  15px;   /* 강조 본문, 카드 제목 */
  --t-xl:  20px;   /* 섹션 제목 */
  --t-2xl: 28px;   /* 주요 수치 */
  --t-3xl: 40px;   /* 히어로 수치 (한 화면에 1~2개만) */
}
```

**대시보드 본문은 13~14px이다.** 18~20px로 쓰고 있으면 화면이 "확대된 것처럼" 보이고
정보 밀도가 죽는다. 글자가 작아서 안 보이는 문제는 **크기가 아니라 대비와 행간**으로 푼다.

### 행간 · 자간
```css
--lh-tight: 1.15;   /* 큰 수치, 헤드라인 */
--lh-base:  1.5;    /* 본문 */
--lh-loose: 1.7;    /* 로그, 코드 */
```
- 큰 글자일수록 행간을 좁힌다. 40px 텍스트에 1.5는 뜬다.
- 자간은 **대문자 라벨에만** 음수가 아닌 양수로 (`letter-spacing: .04em`).
  본문에 자간을 건드리지 않는다.

### 폰트 선택 — "고르는 것" 자체가 신호다
`system-ui` 는 "결정하지 않았다"는 뜻이고 사람은 그걸 알아본다.

기술 대시보드에 잘 맞는 방향:
- **본문**: 중립적이되 개성이 있는 산세리프 — 좁은 폭(condensed)이면 정보 밀도에 유리
- **수치·로그**: 반드시 **고정폭(monospace)**. 이것만 바꿔도 인상이 크게 바뀐다
- 본문과 수치 폰트를 **다르게** 쓰는 것이 기술 제품의 표준 문법이다

```css
--font-sans: "본문폰트", system-ui, sans-serif;   /* fallback 은 남기되 첫 항목을 지정한다 */
--font-mono: "고정폭폰트", ui-monospace, monospace;
```

폰트 파일은 **로컬에 포함**한다. 폐쇄망 현장에서 CDN 폰트는 로드되지 않는다
(`robot-networking`). 로드 실패 시 fallback으로 레이아웃이 깨지지 않는지 확인한다.

## 2. 간격 — 리듬

**4px 배수만 쓴다. 예외 없이.**

```css
--s-1: 4px;  --s-2: 8px;  --s-3: 12px; --s-4: 16px;
--s-5: 24px; --s-6: 32px; --s-7: 48px; --s-8: 64px;
```

- 5px, 9px, 14px 같은 값이 하나라도 있으면 그 요소만 미묘하게 어긋나 보인다.
- **관련 있는 것은 가깝게, 없는 것은 멀게.** 카드 안 요소 간격(8) < 카드 사이 간격(16)
  < 섹션 사이 간격(32). 이 위계가 없으면 모든 것이 같은 무게로 보인다.
- 카드 패딩은 하나로 통일한다. 카드마다 12/14/16이면 그리드가 흔들린다.

## 3. 색

### 역할로 정의한다
```css
/* 표면 — 어두울수록 뒤 */
--bg:        #0d1117;   /* 페이지 */
--surface-1: #161b22;   /* 카드 */
--surface-2: #21262d;   /* 카드 안 요소, 입력 */
--line:      #30363d;   /* 경계선 */

/* 텍스트 — 대비로 위계 */
--text:      #e6edf3;   /* 본문 */
--text-dim:  #8b949e;   /* 보조 (본문 대비 4.5:1 유지) */
--text-mute: #6e7681;   /* 비활성 */

/* 상태 — 의미 고정, 재사용 금지 */
--ok: … --warn: … --err: … --info: …
/* 액션 — 상태색과 색상(hue)이 겹치면 안 된다 */
--accent: …
```

### 흔한 충돌
**accent(액션)와 warn(경고)이 같은 계열이면** 사용자가 버튼과 경고를 구분하지 못한다.
색상환에서 **최소 60° 이상** 벌린다. 주황 accent를 쓴다면 warn은 노랑이 아니라 다른 축으로.

### 검증
- 본문 대비 **4.5:1**, 큰 글자 3:1 이상. 보조 텍스트도 4.5:1 을 목표로 한다
- **상태를 색만으로 구분하지 않는다** — 색 + 아이콘/패턴 + 텍스트
- 다크에서 채도 높은 색은 진동한다. 채도를 낮춘 변형을 따로 둔다
- 화면을 **회색조로 렌더링**해보고 위계가 유지되는지 본다. 이게 가장 빠른 검증이다

## 4. 형태 — radius · 경계 · 높이

```css
--r-sm: 4px;   /* 배지, 입력 */
--r-md: 8px;   /* 카드, 버튼 */
--r-lg: 12px;  /* 모달, 큰 패널 */
```
**3단계면 충분하다.** 8/10/12/14를 섞으면 형태 언어가 무너진다.
전체 성격을 하나로 정한다 — 각지게 갈지 둥글게 갈지. 섞지 않는다.

깊이 표현은 **하나만 고른다**:
- 경계선(border) 중심 — 기술 대시보드에 잘 맞고 다크 모드에서 안정적
- 그림자(shadow) 중심 — 밝은 배경에 맞음

둘을 동시에 쓰면 지저분해진다. 그림자를 쓴다면 3단계 이하.

## 5. 수치 표시 — 대시보드의 핵심

```css
.num { font-family: var(--font-mono); font-variant-numeric: tabular-nums; }
```

- **`tabular-nums` 는 선택이 아니다.** 없으면 실시간 값이 바뀔 때마다 폭이 변해 덜컹거린다.
  이 한 줄이 "잘 만든 대시보드" 인상의 큰 부분을 차지한다.
- 값과 단위의 크기를 분리한다: 값 `--t-2xl`, 단위 `--t-sm` + `--text-dim`.
  같은 크기로 붙이면 단위가 값처럼 읽힌다.
- **소수 자릿수를 고정**한다. `12.5 → 12.53 → 12.5` 로 흔들리면 안 된다.
- 숫자는 **우측 정렬**, 라벨은 좌측 정렬. 표에서 소수점이 세로로 맞아야 한다.
- 값이 없을 때 `0` 이 아니라 `—` 로 표시한다. 0과 "알 수 없음"은 다르다.
- 갱신 시 색이 번쩍이는 효과를 넣지 않는다. 계속 보는 화면에서는 피로하다.

---

## 6. 밀도

대시보드는 **정보 밀도가 품질**이다. 여백 미학은 랜딩 페이지의 것이다.

- 한 화면에 필요한 정보가 다 들어가되, 그룹 간 경계가 명확해야 한다.
- 스크롤 없이 "지금 문제 있는가"를 판단할 수 있어야 한다.
- 카드 제목은 작고 흐리게(`--t-sm`, `--text-dim`, 대문자 + 자간), 내용은 크고 선명하게.
  제목이 내용보다 눈에 띄면 위계가 뒤집힌 것이다.
- 큰 수치(`--t-3xl`)는 **한 화면에 1~2개만**. 전부 크면 아무것도 크지 않다.

---

## 7. 모션 — 절제

- 상태 전환은 **150~200ms**, `ease-out`. 이보다 길면 느리게 느껴진다.
- 데이터 갱신에 애니메이션을 넣지 않는다. 매초 움직이면 읽을 수 없다.
- 진행률 바 같은 연속 값만 부드럽게 (`transition: width .3s`).
- 장식적 애니메이션은 운영 화면에 넣지 않는다. 8시간 보는 사람에게 방해가 된다.
- `prefers-reduced-motion` 을 존중한다.

---

## 8. 토큰으로 구현

```css
:root{
  /* 위의 --t-*, --s-*, --r-*, 색 전부를 여기 한 곳에 */
}
```

- **컴포넌트에 원시값(raw value)을 쓰지 않는다.** `padding:14px` 이 아니라 `padding:var(--s-3)`.
- 토큰 파일을 **프로젝트 간 공유**한다. G2·X2·D1·Omnihand 대시보드가 각자 다른 값을 쓰면
  같은 회사 제품으로 보이지 않는다. 공통 `tokens.css` 하나를 두고 로봇별로는
  accent 색 정도만 오버라이드한다.
- 단일 HTML 대시보드라도 `:root` 블록만 복사해 쓰면 된다. 빌드 도구가 필요 없다.

## 9. 적용 순서 (기존 화면 개선 시)

기능은 되는데 디자인이 아쉬운 화면을 고칠 때, **이 순서가 효과 대비 비용이 가장 좋다.**

1. **타이포 스케일 정리** — font-size를 7종 이하로 축소. 본문을 13~14px로. ← 효과 가장 큼
2. **간격 4px 배수로 통일**
3. **radius 3단계로 통일**
4. **폰트 지정** — 본문 + 고정폭. `system-ui` 탈출
5. **수치에 tabular-nums + 단위 분리**
6. **색 충돌 해소** (accent vs warn), 대비 검증
7. 토큰으로 추출해 공유

각 단계마다 **스크린샷을 남겨 비교**한다. 1~3번만 해도 대부분 "설계된 것처럼" 바뀐다.

## 어느 스킬을 따를 것인가

| 화면 | 따를 것 |
|---|---|
| **운영자·관제 대시보드, 내부 도구** | 이 스킬 + `ui-ux-design`. **frontend-design 의 "BOLD·비대칭·장식" 은 적용하지 않는다** |
| 제품 소개·랜딩·데모·고객 시연용 | `frontend-design` 의 개성 있는 미학이 주도 |
| 차트·그래프 | 번들 스킬 `dataviz` |
| 접근성 세부 | `accessibility-wcag` |

**대시보드에 커스텀 커서·그레인 오버레이·비대칭 레이아웃을 넣지 않는다.**
전문적으로 보이게 하는 것은 장식이 아니라 **일관성과 정밀함**이다.
