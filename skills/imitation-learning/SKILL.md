# 모방학습 (Imitation Learning)

시연을 모아 정책을 학습한다. **데이터 품질이 알고리즘 선택보다 훨씬 중요하다** —
이 순서를 뒤집으면 몇 주를 낭비한다.

## 정책 선택

| | ACT | Diffusion Policy | VQ-BeT |
|---|---|---|---|
| 구조 | CVAE + Transformer, 액션 청크를 한 번에 예측 | 조건부 디노이징 확산, CNN 비전 인코더 | 벡터 양자화 + 행동 트랜스포머 |
| 추론 속도 | **빠름** (단일 forward) | 느림 (디노이징 반복) | 중간 |
| 데이터 요구 | 적음 (<100 시연에서도 동작) | 더 많음 | 중간 |
| 강점 | 엣지 배포, 높은 제어율, 양팔 작업 | 다중 모드 행동, 접촉이 많은 작업, 시간적 일관성 | 이산적 모드가 뚜렷한 작업 |
| 첫 선택 | **여기서 시작한다** | ACT 로 부족할 때 | 특수 케이스 |

**추천 경로**: ACT 로 베이스라인 → 실패 모드 확인 → 필요하면 Diffusion Policy.
처음부터 확산 모델로 가면 학습·추론 비용 때문에 반복 속도가 죽는다.

Diffusion Policy 참고 설정: 학습 500~2000 epoch, lr 1e-4 코사인 스케줄,
학습은 DDPM 100 스텝 / 추론은 DDIM 10~50 스텝으로 줄여 지연을 낮춘다.

## LeRobot

- 데이터 포맷 `LeRobotDataset`: 상태·액션은 **Parquet**, 영상은 **MP4**.
  스트리밍과 시각화가 가능하고 저장 효율이 좋다.
- 파이프라인: 수집(`lerobot-record`) → 학습(`lerobot-train`) → 평가(`lerobot-record --policy.path`).
- 데이터셋을 허브에 올리면 재현·공유가 쉬워진다. 개체별·태스크별로 분리해 관리한다.

## 데이터 수집 — 여기가 승부처

- **일관성 있게 시연한다.** 사람이 매번 다른 방식으로 하면 정책은 평균을 배우고
  그 평균은 어떤 상황에서도 동작하지 않는다.
- **다양성도 필요하다.** 물체 위치, 조명, 초기 자세를 바꿔가며 수집한다.
  한 위치에서만 100번 수집하면 그 위치에서만 되는 정책이 나온다.
- **실패 시연을 넣지 않는다.** 행동복제는 준 대로 배운다.
  다만 *복구* 시연(살짝 어긋난 상태에서 바로잡는 동작)은 매우 유용하다 —
  분포 이탈(covariate shift) 대응력이 크게 올라간다.
- 시연 중 **멈칫거림(pause)** 을 조심한다. 사람이 망설인 구간을 학습하면
  정책이 그 지점에서 멈춰버린다. 실제로 자주 나오는 실패 모드다.
- 관측·액션의 **시간 정렬**을 확인한다. 카메라 프레임과 관절 상태의 타임스탬프가 어긋나면
  정책은 미래를 보고 행동하는 것을 배우고 실기에서 실패한다.
- 수집 주기(fps)와 배포 시 제어 주기를 **동일하게** 맞춘다. 다르면 동작 속도가 달라진다.

## 관측·액션 공간 설계

- **실기에서 얻을 수 있는 것만 관측에 넣는다.** 시뮬 특권 정보는 배포 시 사라진다.
- 카메라는 시점이 중요하다. 손목 카메라(wrist)는 세밀 조작에, 전역 카메라는 접근에 유리하다.
  둘 다 쓰는 구성이 일반적이다.
- 액션은 **절대 위치**보다 상대 변위(delta)가 일반화가 잘 되는 경우가 많다.
  단 누적 오차가 생기므로 태스크에 맞게 고른다.
- 정규화 통계(mean/std)를 데이터셋에서 계산해 **배포 시에도 동일하게** 적용한다.
  이 통계를 잘못 저장/로드하는 것이 조용한 실패의 흔한 원인이다.

## 액션 청킹

- 한 번에 여러 스텝의 액션을 예측하고 실행한다. 지연을 숨기고 시간적 일관성을 준다.
- 청크 길이는 트레이드오프: 길면 부드럽지만 반응이 느리고, 짧으면 반응은 빠르나 떨린다.
- 청크 경계에서 끊기지 않게 **temporal ensembling**(겹치는 예측의 가중 평균)을 쓴다.
  이걸 빼면 청크마다 튀는 동작이 나온다.

## 평가

- **학습 손실은 성능이 아니다.** 반드시 실기(또는 시뮬)에서 성공률을 센다.
- 성공률은 **여러 초기 조건에서 N회** 측정한다. 20회 미만이면 통계적으로 의미가 약하다.
- 실패를 유형별로 분류한다: 접근 실패 / 파지 실패 / 중간 정지 / 목표 이탈.
  유형이 다르면 처방이 다르다.
- 평가 영상을 남긴다. 숫자만으로는 무엇이 잘못됐는지 알 수 없다.

## 실패 진단

| 증상 | 원인 |
|---|---|
| 학습은 잘 되는데 실기에서 실패 | 관측 분포 차이 — 조명/배경/카메라 자세가 수집 때와 다름 |
| 특정 초기 위치에서만 성공 | 수집 데이터의 다양성 부족 |
| 중간에 멈춤 | 시연에 망설임 구간이 포함됨 / 분포 이탈로 정지 액션 예측 |
| 동작이 떨림 | 청킹/앙상블 없음, 또는 제어 주기 불일치 |
| 조금만 어긋나면 복구 못 함 | 복구 시연 부재 (BC 의 근본 한계) |
| 물체를 놓침 | 그리퍼 액션의 시간 해상도 부족, 또는 힘 피드백 부재 |
| 추론이 제어 주기를 못 따라감 | 확산 스텝 과다 — DDIM 스텝 축소, ACT 로 교체, 또는 TensorRT 변환 |

## 배포

- 추론 지연을 **끝단에서** 측정한다 (이미지 취득 → 액션 적용). 모델 forward 만 재면 의미가 없다.
- 정책 출력에 **안전 클램프**를 건다. 관절/속도 한계, 작업공간 경계.
  학습된 정책은 언제든 이상한 값을 낼 수 있고, 그걸 그대로 하드웨어에 보내면 안 된다.
- 실기 실행 시 **중단 경로**를 항상 확보한다 (E-stop, 데드맨 스위치).
- 배포 후 실패 사례를 다시 수집해 데이터셋에 추가하는 루프를 만든다.
  모방학습은 한 번 학습하고 끝나는 것이 아니라 데이터 순환이 본체다.
