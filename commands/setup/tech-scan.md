---
description: 특정 도메인의 신기술을 조사해 우리 세팅에 반영할지 판단하고 제안한다
---

인자로 도메인을 받는다 (예: `/setup:tech-scan VLA`, `/setup:tech-scan SLAM`,
`/setup:tech-scan 다족보행`). 인자가 없으면 로봇 전 도메인을 훑되 범위를 사용자에게 확인한다.

`setup-maintenance` 스킬의 판단 기준을 따른다.

## 절차

### 1. 현재 상태 파악
- `~/.claude/MANIFEST.md` 를 읽는다
- 해당 도메인의 기존 스킬을 찾아 **무엇이 이미 적혀 있는지** 확인한다.
  기존 내용을 모르고 조사하면 중복 제안만 나온다

### 2. 조사
WebSearch / WebFetch 로 확인한다. 반드시 **현재 날짜 기준**으로 검색한다.

- 그 도메인에서 최근 등장하거나 표준으로 자리 잡은 것
- 기존 스킬에 적힌 내용 중 **더 이상 사실이 아닌 것** ← 이게 가장 중요하다
- 실무 채택률이 있는가, 아니면 논문 단계인가
- 라이선스·유지보수 상태 (마지막 커밋, 이슈 응답)

**과장을 걸러낸다.** 벤치마크 SOTA 와 현장 채택은 다르다.
블로그·마케팅 자료보다 공식 문서·레포 활동을 우선한다.

### 3. 판단

각 항목을 분류한다:

| 분류 | 조치 |
|---|---|
| **정정 필요** | 기존 스킬 내용이 틀렸다 → 즉시 수정 제안 (최우선) |
| **섹션 추가** | 기존 스킬에 한 섹션으로 들어감 |
| **새 스킬** | 독립 주제이고 실제로 쓸 것 |
| **기록만** | 아직 이르다 → MANIFEST 의 "미적용" 에 한 줄 |
| **무시** | 유행이거나 우리와 무관 |

새 스킬을 제안할 때는 `setup-maintenance` 의 체크리스트를 통과했는지 명시한다
(실제로 쓸 것인가 / 기존에 못 들어가는가 / 안정화됐는가 / API 나열이 아닌가).

### 4. 보고

```
## 정정이 필요한 내용
- skills/xxx/SKILL.md 의 "..." → 현재는 ... 로 바뀜 (출처)

## 추가 제안
| 항목 | 분류 | 어디에 | 근거 |

## 기록만 (아직 이름)
- ...

## 변경하지 않을 것
- ... (이유)
```

### 5. 적용

사용자가 승인한 항목만 반영한다. 반영 후:
- `setup-maintenance` 의 검증 스크립트를 돌린다
- `MANIFEST.md` 를 갱신한다
- 출처 URL 을 남긴다

## 원칙

- **확인하지 못한 것을 사실처럼 쓰지 않는다.** 조사 결과가 불확실하면 불확실하다고 적는다.
- 스킬에 넣을 때 **버전 번호나 정확한 CLI 플래그를 깊게 적지 않는다.** 가장 빨리 낡는다.
  선택 기준, 함정, 실패 진단을 적는다.
- 사용자가 승인하지 않은 변경을 하지 않는다. 제안까지가 이 커맨드의 범위다.
