`~/.claude` 구성을 점검하고 문제를 보고한다. `setup-maintenance` 스킬 참고.

## 점검 항목

### 1. 구조 유효성 (자동 검증)
`setup-maintenance` 스킬의 검증 스크립트를 실행한다:
- `settings.json` JSON 유효성, 훅 파일 경로 존재 여부
- 스킬 프론트매터 전수 파싱 (`<name>/SKILL.md` 구조, `description` 존재)
- 에이전트 `name:` 과 파일명 일치
- 훅 파이썬 문법 + 실행 권한

### 2. 훅 동작 검증
훅은 **문법이 맞아도 무동작일 수 있다.** 실제 페이로드로 시험한다.
차단 케이스와 통과 케이스(오탐)를 모두 확인하고 결과를 표로 보고한다.

### 3. 참조 무결성
- 스킬 본문이 가리키는 `references/*.md` 가 실제로 존재하는가
- 스킬끼리 상호 참조하는 이름이 실제 스킬인가 (오타·삭제된 스킬 참조)
  - 단, 하니스 **번들 스킬**(`dataviz`, `artifact-design` 등)은 `~/.claude/skills/` 에
    없어도 정상이다. 오탐으로 보고하지 않는다
- 커맨드가 언급하는 스크립트 경로가 존재하는가
- `CLAUDE.md` 와 `MANIFEST.md` 가 현재 구성과 일치하는가 (개수, 이름)

### 4. 중복·표류
- 같은 내용이 두 스킬에 중복 서술돼 있지 않은가 → 한쪽을 참조로 바꾼다
- 서로 **모순되는 서술**이 있지 않은가 ← 가장 위험하다
- 에이전트 개수가 늘어나 매 세션 비용이 커지지 않았는가
- 실제로 한 번도 안 쓴 스킬/커맨드가 있는가 (있으면 description 이 문제일 수 있다)

### 5. 업스트림 갱신
`MANIFEST.md` 의 출처 레포들이 갱신됐는지 확인한다.

```bash
# 원격 최신 커밋만 확인 (클론 없이)
git ls-remote https://github.com/<owner>/<repo>.git HEAD
```

- 우리가 가져온 파일이 업스트림에서 크게 바뀌었으면 diff 를 확인하고 반영할지 판단한다
- **우리가 수정한 파일**(프론트매터 재작성 등)은 자동으로 덮어쓰지 않는다.
  MANIFEST 의 "처리" 열을 확인한다

### 6. 권한 정책 점검
- `allow` 목록에 **하드웨어를 움직이는 명령이 섞이지 않았는가** ← 반드시 확인
- 자주 프롬프트가 뜨는 안전한 명령이 있으면 allow 추가를 제안
- deny 목록이 여전히 유효한 경로를 가리키는가

## 보고 형식

```
## 깨진 것 (즉시 수정 필요)
- ...

## 표류 (내용 불일치·중복·모순)
- ...

## 업스트림 갱신 있음
| 레포 | 우리 버전 | 원격 | 반영 권장 |

## 정상
- 스킬 N개 파싱 OK / 에이전트 N개 정합 / 훅 N개 동작 확인

## 제안
- ...
```

## 원칙

- 점검만 하고 **자동으로 고치지 않는다.** 수정은 사용자 승인 후.
  단, 명백한 오타나 깨진 경로는 고칠지 물어본다.
- 문제가 없으면 없다고 짧게 말한다. 억지 지적을 만들지 않는다.
- 업스트림을 확인할 때 대용량 클론을 하지 않는다. `git ls-remote` 나 raw 파일 조회로 충분하다.
