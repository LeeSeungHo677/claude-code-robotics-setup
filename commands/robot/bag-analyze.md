rosbag2 파일(또는 디렉토리)을 분석한다. 인자로 경로를 받고, 없으면 현재 디렉토리에서
가장 최근 bag 을 찾는다.

## 절차

1. **기본 정보**
   ```bash
   ros2 bag info <path>
   ```
   기록 시간, 메시지 수, 토픽 목록과 타입, 각 토픽의 메시지 개수를 파악한다.

2. **주기 계산** — 토픽별 실제 발행 주기와 편차를 계산한다.
   메시지 수 / 기록 시간으로 평균을 내되, **가능하면 타임스탬프 간격의 분포**를 본다.
   평균만 보면 중간에 끊긴 구간을 놓친다.

3. **결측·이상 구간 탐지**
   - 기대 주기 대비 간격이 3배 이상 벌어진 구간 → 데이터 유실 또는 노드 중단
   - 타임스탬프가 역행하는 구간 → 시간 동기화 문제 또는 bag 병합 오류
   - 메시지가 갑자기 멈춘 토픽 → 노드 크래시 의심

4. **시간 정합 점검**
   - 헤더 타임스탬프와 기록 시각의 차이가 큰 토픽이 있는가 (센서 드라이버가 취득 시각을 안 넣음)
   - 센서 간 타임스탬프 오프셋이 있는가

5. **TF 점검** — `/tf`, `/tf_static` 이 있으면 어떤 프레임 체인이 기록됐는지,
   끊긴 구간이 있는지 확인한다.

6. **QoS 점검** — bag 메타데이터의 QoS 프로파일을 확인한다.
   재생 시 구독자와 호환되지 않으면 조용히 수신되지 않는다.
   `~/.claude/skills/ros2-engineering/scripts/rosbag2_qos_checker.py` 를 활용할 수 있다.

## 보고 형식

```
## 개요
경로 / 포맷(mcap·db3) / 기록 시간 / 총 메시지 수 / 크기

## 토픽
| 토픽 | 타입 | 개수 | 평균 Hz | 편차 | 비고 |

## 발견된 문제
- /scan 이 12.4초~18.1초 구간에서 끊김 (5.7초 공백) → 센서 드라이버 재시작 의심
- /camera/image_raw 헤더 시각이 기록 시각보다 평균 180ms 이르다 → 취득 시각 확인 필요

## 분석에 쓸 수 있는 것
- PlotJuggler 로 열 신호 추천
- 재생 명령 예시 (필요한 QoS 오버라이드 포함)
```

## 주의

- **bag 을 수정하거나 삭제하지 않는다.** 읽기만 한다.
- 큰 bag 을 전부 디코딩하려 하지 않는다. 메타데이터와 샘플링으로 판단하고,
  전체 스캔이 필요하면 사용자에게 소요 시간을 먼저 알린다.
- 재생(`ros2 bag play`)은 실기에 명령이 나갈 수 있으므로 임의로 실행하지 않는다.
