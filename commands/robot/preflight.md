로봇을 실제로 움직이기 전에 확인해야 할 것들을 점검한다.
**하드웨어를 구동하는 명령은 실행하지 않는다** — 확인만 하고 사용자가 실행하게 한다.

## 점검 항목

### 1. 빌드 · 환경
- 워크스페이스가 최신 소스로 빌드됐는가 (`src/` 수정 시각 vs `install/` 시각)
- `colcon build` 가 경고 없이 통과하는가
- 오버레이 순서가 맞는가 (`echo $AMENT_PREFIX_PATH`)
- `ROS_DOMAIN_ID`, `RMW_IMPLEMENTATION` 이 의도한 값인가
- `use_sim_time` 이 실기 기준으로 false 인가 ← **시뮬 설정이 남아 있으면 TF 가 전부 깨진다**

### 2. 설정 · 캘리브레이션
- 파라미터 파일이 이 로봇 개체에 맞는 것인가
- 캘리브레이션 파일이 존재하고 최신인가 (날짜 확인)
- URDF 의 관절 한계가 실제 하드웨어 스펙과 일치하는가
- 속도·가속도 한계가 시험 조건에 맞게 설정됐는가 (첫 시험이면 낮춰야 한다)

### 3. 안전
- E-stop 동작을 **물리적으로 확인**했는가 (누르고 실제로 멈추는지)
- `/cmd_vel` 등 명령 토픽에 타임아웃이 있는가
- 명령 clamp 가 하드웨어 직전에 적용되는가
- 안전 감시 노드가 제어 스택과 독립 프로세스인가
- 첫 시험 조건이 안전한가 (주변 정리 / 매달아 놓기 / 저속 / 사람 대피)
- 디버그용 안전 우회 코드가 남아 있지 않은가

`robot-safety-reviewer` 에이전트로 코드 레벨 검수를 함께 돌릴 것을 권한다.

### 4. 인터페이스
- 최근 변경된 토픽/서비스/액션의 소비자가 전부 갱신됐는가
- QoS 불일치가 없는가 (`ros2-engineering/scripts/qos_checker.py` 활용)
- TF 트리가 완결되는가, 발행자가 중복되지 않는가

### 5. 관측 가능성
- rosbag 기록 대상 토픽이 정해져 있는가 (문제 발생 시 분석할 근거)
- 디스크 여유가 충분한가
- `/diagnostics` 가 발행되는가
- 로그 레벨이 적절한가 (고주파 경로에 throttle 없는 로그가 없는가)

### 6. 되돌리기
- 현재 상태가 커밋되어 있는가 (문제 시 되돌릴 지점)
- 이전에 동작하던 설정의 백업이 있는가

## 보고 형식

```
## 차단 (해결 전 실기 금지)
- ...

## 경고 (확인 후 진행)
- ...

## 확인 완료
- ...

## 실행 전 사용자가 직접 해야 할 것
1. E-stop 물리 시험
2. 다음 명령으로 저속 모드 기동:  <명령어>
```

체크만 하고 끝내지 않는다. **무엇을 어떤 순서로 실행할지** 마지막에 제시한다.
